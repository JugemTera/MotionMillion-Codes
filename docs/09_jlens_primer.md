## 0. 全体の見取り図

J-Lens（Jacobian lens）は、学習済みの Transformer の**途中の層の状態**を、**最終層と同じ語彙**で読み出すための道具である。本リポジトリの語彙は英単語ではなく FSQ の**モーションコード**（64,000 個）なので、読み出した結果はデコードして「動き」として見ることができる。

全体の筋道は次の 6 段で、本文もこの順に進む。

0. 動きは 1 フレーム 272 次元の実数列（ルートの速度・向きの変化、22 関節の位置・速度・回転）として保存され、FSQ トークナイザで 2 フレームごとに 1 個の整数「コード」に変換されてからモデルに入る（§1）。
1. モデルは「テキスト ＋ これまでのコード列」から「次のコード」を当てる（§2）。
2. Transformer は、各位置のベクトルに層ごとの修正を**足し込んでいく**構造で、最後にそのベクトルを語彙に変換する（§3）。
3. 途中の層のベクトルをそのまま語彙に変換しても、浅い層ではうまく読めない。以降の層が加える変換を**一次近似（ヤコビアン）**で代用すると読めるようになる、というのが J-Lens の主張（§4, §5）。
4. 位置をまたぐ影響を扱うために、どの位置からどの位置への微分を平均するかを決める必要がある。それが `motion` / `text_to_motion` / `offset` の各モード（§6, §8）。
5. 読み出しは「次のコードの確率分布」なので、argmax を取ってデコードすれば 2 フレームの動きになり、方向を逆向きに使えば残差に足して生成を操作できる（§7, §9）。

## 1. データ ―― モーションはどう表現されているか

J-Lens の読み出しは最終的に「動き」として見るので、その動きがどんな数の並びとして保存され、どこまでが前処理でどこからがモデルかを先に押さえておく。本節は MotionMillion の生データ（`.npy`）から LLaMA に入るコード列までを順に追う。

### 1.1 1 本のモーションは「フレーム × 272」の行列

モーション 1 本は 1 つの `.npy` ファイルで、形は $(T, 272)$ の float64 配列である。$T$ はフレーム数、1 行が 1 フレーム（1/30 秒）の姿勢と動きを表す 272 個の実数である。

```
dataset/MotionMillion/motion_data/vector_272/<name>.npy   形 (T, 272)、30 fps
dataset/MotionMillion/texts/<name>.txt                    1 行 1 キャプション（複数行）
dataset/MotionMillion/mean_std/vector_272/{mean,std}.npy  各 (272,)、正規化用
dataset/MotionMillion/split/version1*/t2m_60_300/*.txt    <name> の一覧（分割）
```

例として `MotionGV/folder0/000002.npy` は 322 行、つまり約 10.7 秒の動きである。`<name>` は `MotionGV/folder0/000002` のような相対パスで、モーションとキャプションを結び付ける鍵になる。

骨格は SMPL-X の体幹 22 関節（HumanML3D と同じ関節順。`utils/paramUtil.py` の `t2m_kinematic_chain` が親子関係）で、手指や表情は含まない。

### 1.2 272 次元の内訳

MotionMillion の論文は 1 フレームの表現を

$$
x_i = \{\dot r_x,\ \dot r_z,\ \dot r_a,\ p_i,\ v_i,\ r_i\}
$$

と定義している。コード（`utils/motion_process.py`）で確かめた実際の並びは次の通りで、関節数 $N = 22$ とすると $2 + 6 + 3N + 3N + 6N = 272$ になる。

| 列の範囲 | 次元 | 記号 | 内容 | 基準 |
|---|---|---|---|---|
| 0〜1 | 2 | $\dot r_x, \dot r_z$ | ルート（腰）の水平面上の並進速度 | 向きを除いた局所座標、前フレームとの差 |
| 2〜7 | 6 | $\dot r_a$ | ルートの向き（鉛直軸まわりの回転）の 1 フレームあたりの変化。6D 回転表現 | 前フレームに対する相対回転 |
| 8〜73 | 66 = 22×3 | $p_i$ | 22 関節の位置 (x, y, z) | ルート基準・向きを除いた座標。ルート自身は x = z = 0、y = 腰の高さ |
| 74〜139 | 66 = 22×3 | $v_i$ | 22 関節の速度 | 上の位置の前フレームとの差分。先頭フレームは 0 |
| 140〜271 | 132 = 22×6 | $r_i$ | 22 関節の回転。6D 回転表現 | 親関節に対する相対回転（SMPL の関節回転と同じ意味） |

具体的に `000002.npy` の先頭フレームを見ると、ルート速度は $(0, 0)$、向きの変化は $(1, 0, 0, 0, 1, 0)$（単位回転）、ルート位置は $(0, 0.91, 0)$（高さ 0.91 m）、ルートの回転もほぼ単位回転で、「静止した状態から始まる」ことが数字で読める。

**6D 回転表現**とは、$3 \times 3$ 回転行列の最初の 2 列（6 個の数）をそのまま並べたものである。クォータニオンやオイラー角と違って不連続点がなく、ニューラルネットの出力として扱いやすい。元の行列に戻すときは 2 本のベクトルを直交化して 3 本目を外積で作る（`rotation_6d_to_matrix`）。

> 補足: `utils/losses.py` のコメントにある `(nb_joints - 1) * 12 + 4 + 3 + 4` は HumanML3D の 263 次元表現の式で、272 には当てはまらない。実際の内訳は上の表と `recover_from_local_position` / `recover_from_local_rotation` のスライス（`[:, :2]`, `[:, 2:8]`, `[:, 8:8+3N]`, `[:, 8+6N:8+12N]`）で確かめられる。

### 1.3 なぜこの形なのか

**位置と向きは「変化量」で持つ。** 絶対座標で持つと、同じ「前に歩く」でも開始地点や向きが違えば別の数列になり、モデルはそれまで覚えなければならない。ルートの並進と向きを 1 フレームごとの変化量にし、関節位置もルート基準・向き除去で持てば、どこでどちらを向いて始めても同じ動きは同じ数列になる（平行移動と水平回転に対する不変性）。復元するときは変化量を累積和（`cumsum`）で足し上げて軌跡と向きを取り戻す。

**位置と回転の両方を持つ。** 一見冗長だが、位置だけでは骨の軸まわりのねじれが決まらず、SMPL や BVH に戻すのに逆運動学（IK）が要る。回転があれば IK なしで SMPL-X のパラメータへ直接変換でき、両者が同じ骨格から導かれているので互いの誤りを抑える正則化にもなる、というのが論文の主張である。HumanML3D の 263 次元表現は回転成分に誤りがあったため、それを直したものとして提案されている。

**速度も持つ。** 位置から計算できる冗長な量だが、トークナイザの損失で速度・加速度を直接比べるために入れてある（`ReConsLoss.forward_vel` / `forward_acc`）。

### 1.4 正規化

モデル（トークナイザの入出力）が扱うのは生の値ではなく、次元ごとに平均を引いて標準偏差で割った値である。

$$
\tilde x = \frac{x - \mu}{\sigma}, \qquad \mu, \sigma \in \mathbb{R}^{272}\ (\texttt{mean.npy}, \texttt{std.npy})
$$

速度のような小さい量（$\sigma \approx 0.008$）と高さのような大きい量（$\mu \approx 0.85$）を同じ尺度に揃えるためで、デコード後は $\sigma \tilde x + \mu$ で元に戻してから関節へ復元する。J-Lens 自体はこの空間に触れないが、§7 で読み出しを動きに戻すときに通る。

### 1.5 データセットの規模と分割

| 項目 | 内容 |
|---|---|
| データ源 | `MotionGV`, `MotionLLAMA`, `MotionUnion`, `PhantomDanceDatav1.1` の各ディレクトリ（`Mirror_` 付きは左右反転版） |
| 分割ファイル | `split/version1/t2m_60_300/{train,val,test,all}.txt`。`<name>` を 1 行ずつ列挙 |
| 配布元の全体（version1） | all 876,766 本、val 44,044 本 |
| 手元にある分（version1_avail） | all 359,075 本、val 17,983 本 |

`version1_avail` は `prepare/arrange_motionmillion.py` が「実体ファイルが存在する名前だけ」を抜き出して書いたもので、HumanML3D など Hugging Face の配布に含まれないデータが欠けている分だけ少ない。J-Lens の fit はこの `version1_avail` の val から例を抽出している。`t2m_60_300` は T2M 用に長さで絞った分割で、トークナイザ学習用の `tokenizer_96` とは別である。

### 1.6 コード列への変換と `all_data.pkl`

LLaMA は 272 次元の実数列を直接は読まない。FSQ トークナイザ（§2.3）が $(T, 272)$ を時間方向に 2 分の 1 に縮め、$T/2$ 個のコード（0〜63,999 の整数）にする。コード 1 個が 2 フレーム = 1/15 秒である。

この変換を全モーションに一度だけ掛け、結果をキャプションと一緒に 1 つのファイルにまとめたのが `all_data.pkl` である。

```python
all_data = {
    "text_data": {name: [caption1, caption2, ...]},   # texts/<name>.txt の各行
    "code_data": {name: [codes]},                     # 長さ T/2 の整数配列（通常 1 本）
    "file_names": [...],
}
```

学習と J-Lens の fit はこのファイルだけを読み、`.npy` には触れない（`fit_jlens.py` の `sample_pairs`）。1 本のモーションに複数のキャプションがある場合は乱数で 1 つ選ぶ。J-Lens 用には val 分割（17,983 本）だけでこのファイルを作り直してある（`job/job_get_codes_jlens_val.sh`）。

ここまでをまとめると、データの流れは

```
.npy (T, 272, 30 fps) ──正規化──► FSQ エンコーダ ──► コード列 (T/2 個) ──┐
                                                                        ├──► all_data.pkl ──► LLaMA / J-Lens
.txt (キャプション)  ─────────────────────────────────────────────────┘
```

で、J-Lens の読み出しを「動き」として見るには、この矢印を逆向きに辿る（コード → FSQ デコーダ → 272 次元 → 逆正規化 → 関節）。それが §7 の内容である。

> コード: `dataset/dataset_tokenize.py`（`joints_num = 22`, `fps = 30`, `dim_pose = 272`、正規化）、`utils/motion_process.py` `recover_from_local_position` / `recover_from_local_rotation`（内訳と復元）、`utils/quaternion.py` `cont6d_to_matrix`（6D 回転）、`prepare/arrange_motionmillion.py`（配置と `version1_avail`）、`train_t2m_get_codes.py`（`all_data.pkl` の生成）。

## 2. モデルが解いている問題

### 2.1 入力と出力

T2M（text-to-motion）の LLaMA は、1 本の系列を受け取り、各位置で「次に来るコード」の確率分布を出す。系列の形は次の通り（`docs/08` 図 2）。

```
[ t_0 … t_{Lt-1} | c_0 c_1 … c_{N-1} | END | PAD … ]
   テキスト位置        モーション位置
```

- $t_j$: キャプションを T5 で符号化した埋め込みを、線形層 `llama_proj` で LLaMA の次元に写したもの。語彙のトークンではなく連続ベクトル。$L_t$ はキャプションのサブワード数（最大 150）。
- $c_i$: FSQ トークナイザが出したモーションコード。0〜63,999 の整数で、1 個が 2 フレーム（30 fps なので 1/15 秒）に相当する。
- END（64,000）とPAD（64,001）は特別なトークン。

### 2.2 「次のコードを当てる」とは

位置 $p$ の出力は「位置 $p+1$ に来るトークン」の予測である。モーション位置 $p = L_t + i$ はコード $c_i$ を持ち、その出力は $c_{i+1}$ を当てる。テキストの最後の位置 $L_t - 1$ の出力が $c_0$ を当てる。途中のテキスト位置は何も当てるよう学習されていない（損失が入らない）。

学習は、正解の系列を丸ごと入れて全位置の予測を同時に採点する（teacher forcing）。推論は、テキストだけを入れて最後の位置の予測を 1 個採用し、それを系列に足してまた予測する、を END が出るまで繰り返す（自己回帰）。

### 2.3 コードとは何か、なぜ 64,000 個あるのか

**コードとは「2 フレーム分の動きに付けた整数の名前」である。** 64,000 という数はデータから決まったものではなく、設計者が選んだ量子化の格子の大きさである。

#### なぜ動きを整数にするのか

LLaMA は言語モデルと同じ「次のトークンを当てる」モデルで、入力も出力も有限個の記号（語彙）でなければならない。動きは 272 次元の連続値なので、そのままでは扱えない。そこでトークナイザ（FSQ 付きの VQ-VAE）を学習し、動きの短い区間を有限個の記号のどれかに割り当てる。この記号がコードで、言語モデルの単語に相当する。

#### トークナイザがやっていること

1. エンコーダ（畳み込みネット）が 272 次元のフレーム列を読み、時間方向に 2 分の 1 に縮め、2 フレームにつき 1 本の連続ベクトルを出す。
2. そのベクトルを線形層で **6 次元のベクトル** $(z_1, \ldots, z_6)$ に落とす。ここまでは普通の実数で、丸めはまだしていない。
3. 6 つの要素それぞれを、決められた段階数の整数に**丸める**（量子化）。丸めた結果は有限通りしかない。
4. 丸めた 6 つの整数の組に通し番号を付ける。それがコード番号。
5. デコーダは逆に、6 つの数の列から 272 次元のフレーム列を復元する。

エンコーダとデコーダは「元の動きを復元できるように」学習されるが、丸める規則そのものは固定で学習されない。丸めは微分できないので、学習時は「順方向では丸め、逆伝播では丸めを無かったことにする」straight-through 推定で勾配を通す。

#### FSQ の丸め方（64,000 の正体）

FSQ（Finite Scalar Quantization）では、6 つの要素それぞれに「何段階に丸めるか」を決める。本モデルの設定は

$$
\text{levels} = [8,\ 8,\ 8,\ 5,\ 5,\ 5]
$$

で、1〜3 番目の要素は 8 段階（値は 0〜7）、4〜6 番目は 5 段階（0〜4）に丸める。手順は、各要素を $\tanh$ で有界な範囲に押し込み、その範囲を等間隔に区切った点に四捨五入する、というだけである。

丸めた結果の組み合わせの総数は

$$
8 \times 8 \times 8 \times 5 \times 5 \times 5 = 64{,}000
$$

である。コード番号はこの組み合わせに付けた通し番号で、各要素の段階を $a_1, \ldots, a_6$ とすると

$$
\text{index} = a_1 + 8\,a_2 + 64\,a_3 + 512\,a_4 + 2560\,a_5 + 12800\,a_6
$$

という、桁ごとに基数が違う位取り記数法（混合基数）になっている。基数の列 $[1, 8, 64, 512, 2560, 12800]$ が `models/FSQ.py` の `_basis` である。**コード番号は 6 桁の数であり、どの番号も 6 つの座標に戻せる。** 本稿で「コードは 6 軸の格子点」と言うのはこの意味である（§7.2 で使う）。

デコーダに入るのはコード番号ではなく、丸めた 6 つの数を $-1$〜$1$ に正規化したベクトルである。LLaMA 側では、コード番号を埋め込み表 `wte` で $d$ 次元に変換して使う。

#### なぜ 65,536 ではなく 64,000 なのか

- 設計者は語彙を $2^{16} = 65{,}536$ 程度にしたいと決めた。学習スクリプトの `--nb-code 65536` はその希望の値である。
- しかし FSQ では総数が「各軸の段階数の積」にしかなれない。65,536 を 6 個の小さな整数の積で作るには $4^8$ のように段階を細かくするしかなく、FSQ の論文は各軸 5 段階以上を推奨している。その推奨に従って $2^{16}$ に最も近い構成が $[8,8,8,5,5,5] = 64{,}000$ で、これは FSQ 論文の推奨表そのままである。
- `models/vqvae.py` の他の分岐も同じ事情で、名目と実数がずれている。

| 名目（`--nb-code`） | levels | 実際の総数 |
|---|---|---|
| 256 | [8, 6, 5] | 240 |
| 512 | [8, 8, 8] | 512 |
| 1024 | [8, 5, 5, 5] | 1,000 |
| 2048 | [8, 8, 6, 5] | 1,920 |
| 4096 | [7, 5, 5, 5, 5] | 4,375 |
| 16384 | [8, 8, 8, 6, 5] | 15,360 |
| 65536 | [8, 8, 8, 5, 5, 5] | 64,000 |

モデルの出力層 `lm_head` の行数は実数の 64,000 に END を足した 64,001、埋め込み表 `wte` は PAD も足した 64,002 で作られている。J-Lens 側も `--nb-code 64000` を渡す必要がある（65,536 のままだと重みの形が合わず読み込みに失敗する。上流 issue 4 も同じ原因）。

#### なぜ格子を固定するのか（VQ-VAE との違い）

従来の VQ-VAE は「代表ベクトルの表（コードブック）」を学習するが、表の一部しか使われなくなる崩壊（codebook collapse）が起きやすい。FSQ は表を持たず固定の格子に丸めるだけなので、全コードが自然に使われやすく学習も安定する。代償として、コード番号の意味は「6 つの座標」としてしか構造を持たず、各座標が動きの何に対応するかは学習任せになる。それを後から調べる手段の一つが、J-Lens の読み出しをデコードして見ることである。

#### 1 コードの中身を具体的に言うと

あるコード番号は 6 つの座標、例えば $(0, 1, 2, 2, 4, 2)$ のような組に分解できる。この 6 つの数をデコーダに（前後のコードと一緒に）通すと、272 次元 × 2 フレーム、つまり 1/15 秒分の「ルートの速度・向き・関節の位置と回転」が出てくる。コードが 1 つ違えば、この 2 フレームの動きが少し違う、という対応である。

#### まとめ（よくある確認）

- 「トークナイザはベクトルを 6 次元にしているのか」: はい。エンコーダ最後の線形層の仕事。
- 「FSQ は 6 次元ベクトルの各要素を 8 段階（または 5 段階）の整数に直しているのか」: はい。値は 0〜7（または 0〜4）。
- 「64,000 は何で決まるのか」: 各要素の段階数の積。段階数は設計者の選択で、$2^{16}$ に近づけるための FSQ 論文の推奨構成。

> コード: `models/vqvae.py` の FSQ 分岐（levels の選択）、`models/FSQ.py` の `bound` / `quantize` / `codes_to_indices` / `indices_to_level_indices`、`_basis`。

### 2.4 AE・VAE・VQ-VAE・FSQ の関係

「VQ-VAE」という名前が出てくるので、ここで系譜を整理しておく。

**オートエンコーダ（AE）**: 入力 $x$ をエンコーダで低次元の潜在ベクトル $z$ に圧縮し、デコーダで $\hat x$ に戻して $x \approx \hat x$ になるよう両方を学習する。$z$ は決定的な 1 点で、確率は出てこない。

**VAE**: エンコーダが 1 点ではなく $z$ の**分布のパラメータ**（正規分布の平均 $\mu(x)$ と分散 $\sigma(x)^2$）を出す。学習時はこの分布から $z = \mu + \sigma\,\epsilon$（$\epsilon \sim N(0, I)$）を 1 つサンプリングしてデコーダに通す。損失は復元誤差と、$N(\mu, \sigma^2)$ が標準正規からどれだけ離れているかの KL 項の和。「ノイズを入力に戻す」のではなく「入力から作った分布のサンプルを入力に戻す」のであって、ノイズ $\epsilon$ は再パラメータ化のための揺らぎに過ぎない。KL 項で潜在空間が標準正規の周りに整うので、学習後は $N(0, I)$ からサンプルしてデコードすれば新しいデータが生成できる。これが VAE が生成モデルと呼ばれる理由である。

**VQ-VAE（Vector Quantized VAE）**: 潜在を連続ではなく**離散**にしたもの。

1. エンコーダが連続ベクトル $z_e(x)$ を出す。
2. あらかじめ用意した $K$ 本の代表ベクトルの表（コードブック $\{e_1, \ldots, e_K\}$）から、$z_e$ に最も近い $e_k$ を選ぶ。これが量子化で、$k$ がコード番号。
3. デコーダは $e_k$ から $\hat x$ を復元する。
4. 「最も近いものを選ぶ」は微分できないので、逆伝播では $z_e$ にそのまま勾配を流す（straight-through）。コードブックは「選ばれた $e_k$ を $z_e$ に近づける」損失で学習し、エンコーダには「$z_e$ を $e_k$ から離れすぎないようにする」commitment 損失を掛ける。

名前に VAE が付いているのは「潜在に事前分布を置く」枠組みを引き継いでいるためだが、実際には**サンプリングも KL 項も無く**、「離散の潜在を持つオートエンコーダ」と思うのが実態に近い。VAE の「分布からサンプルする」役割は、VQ-VAE では後段の自己回帰モデル（ここでは LLaMA）が「次のコードの分布」を出すことで担う。

**FSQ（本モデル）**: クラス名は `HumanVQVAE` だが、量子化器に FSQ を選ぶとコードブック（学習される表）は無く、6 次元の格子に丸めるだけになる（§2.3）。学習されるのはエンコーダとデコーダだけで、量子化は固定規則。確率的な要素は無く、同じ動きを入れれば必ず同じコード列が出る。損失は復元誤差（272 次元の L1 系）と速度の誤差で、KL 項に相当するものは無い。

| | 潜在 $z$ | 量子化 | 確率・サンプリング | 学習されるもの |
|---|---|---|---|---|
| AE | 連続 1 点 | なし | なし | エンコーダ、デコーダ |
| VAE | 連続、分布 $N(\mu, \sigma^2)$ | なし | あり（KL 項） | エンコーダ、デコーダ |
| VQ-VAE | 離散（表の 1 本） | 最近傍探索 | なし | エンコーダ、デコーダ、コードブック |
| FSQ（本モデル） | 離散（格子点） | 各軸で丸め | なし | エンコーダ、デコーダ |

**J-Lens との関係で押さえる点**: トークナイザは「動き ↔ コード列」の決定的な辞書であり、確率を持たない。確率を持つのは LLaMA の「次のコードの分布」だけで、J-Lens が読み出すのもその分布である。

> コード: `models/vqvae.py` の `HumanVQVAE` / `VQVAE_251`（エンコーダ・量子化器・デコーダの組み立て）、`train_tokenizer.py`（復元誤差と速度誤差）。

## 3. Transformer の最小限

### 3.1 トークンはベクトルになる

各位置のトークンは、まず $d$ 次元のベクトルに変換される。3B モデルでは $d = 3200$、7B では $4096$。コードは埋め込み表 `wte`（64,002 行 × $d$ 列）の該当行、テキスト位置は `llama_proj` の出力がそのベクトルになる。

この「位置 $p$ の $d$ 次元ベクトル」を $h_{0,p}$ と書く（0 は「0 層目、つまり入力」の意味）。

### 3.2 残差ストリーム: 足し算の連鎖

Transformer のブロック（層）は $L$ 個（3B は 24、7B は 36）積まれている。重要なのは、各ブロックが**入力を置き換えるのではなく、入力に修正量を足す**ことである。

$$
h_{\ell} = h_{\ell-1} + \mathrm{Attn}_\ell(h_{\ell-1}) + \mathrm{FFN}_\ell(h_{\ell-1} + \mathrm{Attn}_\ell(h_{\ell-1}))
$$

（正規化層は省いた。）つまり最終層の出力は

$$
h_L = h_0 + \sum_{\ell=1}^{L} (\text{層 } \ell \text{ が足した量})
$$

という**和**になる。この「層をまたいで流れていく $d$ 次元ベクトル」を**残差ストリーム**と呼ぶ。各層は残差ストリームに書き込む、という比喩で語られる。

この構造のおかげで、途中の層の $h_\ell$ と最終層の $h_L$ は**同じ空間に住むベクトル**である。「途中の層を最終層と同じ方法で読む」という発想（§4）が意味を持つのはこのためである。

### 3.3 ブロックの中身: 注意と FFN

ブロックは 2 つの部品からなる。中身の式は本稿には不要で、「何を混ぜるか」だけ押さえればよい。

- **注意（Attention）**: 位置 $p$ のベクトルを更新するとき、**他の位置**のベクトルを重み付きで取り込む。重みは $p$ と各位置の内容の相性で決まる。これが「文脈を見る」部品であり、位置をまたぐ情報の流れは**ここでしか**起きない。
- **FFN（Feed-Forward Network）**: 位置ごとに独立に、ベクトルを非線形関数に通す。他の位置は見ない。「その位置の内容を加工する」部品。

どちらも出力を残差ストリームに**足す**。

### 3.4 最後の読み出し: 正規化と unembedding

最終層の $h_{L,p}$ を語彙の確率分布に変えるのが最後の 2 段である。

$$
\mathrm{logits}_p = W_U \,\mathrm{norm}(h_{L,p}), \qquad P(\text{次} = c) = \mathrm{softmax}(\mathrm{logits}_p)_c
$$

- $\mathrm{norm}$ は RMSNorm（`ln_f`）。ベクトルの長さを揃える操作で、**方向だけを残す**と思ってよい。
- $W_U$ は unembedding 行列（`lm_head`、64,001 行 × $d$ 列）。各行 $W_U[c]$ はコード $c$ に対応する $d$ 次元ベクトルで、$\mathrm{logits}_p[c]$ は $h$ と $W_U[c]$ の内積である。つまり「$h$ が $W_U[c]$ の方向をどれだけ向いているか」がコード $c$ の点数になる。

この見方は後で繰り返し使う。**語彙の各コードは、残差空間の 1 つの方向である。**

### 3.5 位置と因果

通常の自己回帰 Transformer では、位置 $p$ は自分より前の位置しか見ない（因果マスク）。その結果、

> 位置 $q$ の出力は、位置 $p \le q$ の入力にしか依存しない。

という性質が成り立つ。「後ろの入力を変えても前の出力は変わらない」。これは §6 で微分がゼロになる理由として効く。

### 3.6 このモデル固有の点

- テキスト位置同士は**双方向**に見える（マスクの OR）。モーション位置は因果。テキスト位置はモーションを見ない。
- テキスト位置の出力には学習が入っていないので、そこで `lm_head` を通しても意味のある分布にならない。
- 詳細は `models/lit_llama/model_hf.py` の `forward` と `CausalSelfAttention.forward`、図は `docs/08` §4。

### 3.7 数字の整理

| 記号 | 意味 | 3B | 7B |
|---|---|---|---|
| $d$ | 残差ストリームの次元 | 3200 | 4096 |
| $L$ | 層の数 | 24 | 36 |
| $V$ | 語彙（出力） | 64,001 = コード 64,000 + END | 同左 |
| $L_t$ | テキスト位置の数 | キャプション依存、最大 150 | 同左 |
| $N$ | モーションコードの数 | クリップ依存、最大 ~150 | 同左 |

> コード: `jlens_motion/model.py` の `MotionLensModel.forward` が「ブロック列を通して $h_L$ を返す」、`unembed` が「$W_U\,\mathrm{norm}(\cdot)$」。

## 4. 「途中の層を読む」という発想

### 4.1 logit lens

最終層の読み出し $W_U\,\mathrm{norm}(h_{L,p})$ の $h_{L,p}$ を、途中の層の $h_{\ell,p}$ に差し替えてみる。

$$
\mathrm{logitlens}_\ell(h_{\ell,p}) = W_U\,\mathrm{norm}(h_{\ell,p})
$$

これが **logit lens** である。「層 $\ell$ まで計算した時点で、もし以降の層が何もしなかったら、何を出力するか」を見ている。

### 4.2 なぜうまくいくことがあるのか

§3.2 の通り $h_L = h_\ell + (\ell$ 以降の層が足す量$)$ である。後半の層が足す量が小さい、あるいは既に $h_\ell$ が向いている方向を強める程度なら、$h_\ell$ を読んでも $h_L$ を読んでも argmax は同じになる。言語モデルでは後半の層でこれが成り立つことが多く、「何層目で答えが決まるか」を見る道具として使われてきた。

### 4.3 なぜ浅い層で失敗するのか

浅い層では、以降の層が足す量が大きく、しかも**方向を回転させる**。浅い層の $h_\ell$ が持っている情報は、まだ $W_U$ の行が張る「出力用の座標系」に置かれていない。言い換えると、$h_\ell$ の中には「このあと層 $\ell+1 \ldots L$ の処理を経て初めてコード $c$ の方向になる」成分が入っているが、$W_U$ はそれを読めない。

ここで必要なのは、「以降の層が $h_\ell$ をどう変換するか」を考慮に入れた読み出しである。それが J-Lens の出発点になる。

> コード: `jlens_motion/lens.py` の `lens_readout(..., lens=None)` が logit lens（$W_U\,\mathrm{norm}(h_{\ell,p})$ をそのまま計算する経路）。追加の fit は不要で、重みがあれば即座に使える。`tests/test_jlens_motion.py` で「単位行列のレンズ ＝ logit lens」「最終層の読み出し ＝ モデル出力」が確認されている。一致率・KL を層ごとに集計する評価スクリプトは未実装（§7.5）。

## 5. ヤコビアン ―― 「以降の層」を 1 枚の行列で代用する

### 5.1 一変数の微分から

関数 $f(x)$ の $x_0$ での微分 $f'(x_0)$ は、「$x$ を少し動かしたとき $f$ がどれだけ動くか」の比である。

$$
f(x_0 + \delta) \approx f(x_0) + f'(x_0)\,\delta
$$

右辺は $f$ を $x_0$ の近くで直線（一次式）に置き換えたものである。

### 5.2 多変数: ヤコビアン行列

入力が $d$ 次元ベクトル $h$、出力も $d$ 次元ベクトル $f(h)$ のとき、同じことをすると

$$
f(h + \delta) \approx f(h) + J\,\delta, \qquad J_{ij} = \frac{\partial f_i}{\partial h_j}
$$

となる。$J$ は $d \times d$ の行列で**ヤコビアン**と呼ぶ。

- $J$ の第 $j$ **列**: 入力の第 $j$ 成分だけを 1 動かしたとき、出力の各成分がどう動くか。
- $J$ の第 $i$ **行**: 出力の第 $i$ 成分を動かすには、入力のどの成分がどれだけ効くか（出力成分 $i$ の勾配）。

### 5.3 このモデルでの $f$ とは

層 $\ell$ の残差 $h_\ell$ を入力、最終層の残差 $h_L$ を出力とする関数を $f_\ell$ と書く。

$$
h_L = f_\ell(h_\ell) = (\text{ブロック } \ell+1 \text{ から } L \text{ までを順に通す})
$$

$f_\ell$ は注意と FFN を含む複雑な非線形関数だが、そのヤコビアン

$$
J_\ell = \frac{\partial h_L}{\partial h_\ell} \quad (d \times d)
$$

は「層 $\ell$ の残差をある方向に少し動かすと、最終残差がどの方向にどれだけ動くか」をすべて記述する。**以降の層全部の振る舞いを、1 枚の行列に一次近似で畳み込んだもの**である。

$h_\ell$ は残差ストリームなので、$f_\ell$ の中には「$h_\ell$ をそのまま通す」部分がある（§3.2 の和の第 1 項）。したがって

$$
J_\ell = I + \frac{\partial\,(\ell \text{ 以降の層が足す量})}{\partial h_\ell}
$$

と書ける。第 1 項の単位行列 $I$ が「何もしない」部分、第 2 項が「以降の層が加える変換」である。

### 5.4 平均をとる意味

ヤコビアンは入力ごとに違う（$f_\ell$ は非線形なので、どの $h_\ell$ の周りで微分するかで値が変わる）。J-Lens では、多数の実例（例えば 1000 本の系列）とその中の多数の位置で $J_\ell$ を計算し、**平均**する。

$$
\bar J_\ell = \mathbb{E}_{\text{例},\,\text{位置}}\left[\frac{\partial h_L}{\partial h_\ell}\right]
$$

平均することで「このモデルが普通の入力に対して、層 $\ell$ 以降で典型的に行う線形変換」が 1 枚得られる。個々の例に固有の挙動（特定の注意ヘッドがその例だけで効く、など）は潰れるが、その代わりどの例にも使い回せる固定の読み出し器になる。これは学習ではなく平均なので、過学習の心配はなく、必要な例数も少ない（公式の経験則では 100 例程度で実用、1000 例で飽和）。

以下、文脈から明らかなときは $\bar J_\ell$ も単に $J_\ell$ と書く。

### 5.5 J-Lens の読み出し式

logit lens の $h_{\ell,p}$ を、$J_\ell$ で最終層まで「運んだ」ベクトルに置き換える。

$$
\mathrm{lens}_\ell(h_{\ell,p}) = W_U\,\mathrm{norm}(J_\ell\, h_{\ell,p})
$$

これが J-Lens である。構造として見ると、

```
元のモデル    h_0 → B_1 → … → B_ℓ → B_{ℓ+1} → … → B_L → norm → W_U
J-Lens(層ℓ)  h_0 → B_1 → … → B_ℓ → [ J_ℓ ] ─────────→ norm → W_U
```

層 $\ell$ 以降のブロックを行列 1 枚で置き換えたモデルである。$\ell = L$ なら $J_L = I$ で元のモデルに一致する。

なお、§5.2 の一次近似には定数項 $f(h)$ があるが、読み出しでは $J_\ell h_\ell$ だけを使う。残差ストリームの各成分は「方向が意味を持つ」量であり、$J_\ell$ は「層 $\ell$ の方向が最終層のどの方向に対応するか」を写す**座標変換**として使われている。最後の $\mathrm{norm}$ がスケールを消すので、方向さえ正しく運べればよい。

### 5.6 logit lens との関係

§5.3 の分解から、logit lens は「$J_\ell \approx I$ と仮定した J-Lens」である。後半の層で logit lens が効くのは、そこで第 2 項が小さいから。浅い層で効かないのは第 2 項が大きいから。J-Lens はこの第 2 項を実測して補う。公式論文はこれを「logit lens の原理的な補正」と呼んでいる。

### 5.7 この近似が意味するもの、しないもの

- **意味するもの**: 「層 $\ell$ の残差が、以降の処理を経て最終的にどのコードの方向へ向かうか」の、平均的・線形な見積もり。
- **意味しないもの**: 層 $\ell$ が「既にそのコードを決めている」こと。読み出しは予測であって、層 $\ell$ 単独の出力ではない。
- **壊れる場所**: 以降の層が入力に対して強く非線形に振る舞うとき（分布から外れた残差、大きな介入）。また平均なので例ごとの固有の経路は見えない。
- **だから必ずやること**: 読み出しが最終出力と一致する層かどうかを、順位や KL で先に測る（§7.5）。一致しない層では、以降の説明のどれも成り立たない。

> コード: `jlens_motion/lens.py` の `JacobianLens.transport`（$J_\ell h$）と `lens_readout(..., lens=lens)`。

## 6. 位置を考えに入れる ―― S と T

ここまでは 1 つの位置のベクトル $h_{\ell,p}$ だけを考えていたが、実際の $f_\ell$ の入力は「全位置のベクトルの列」で、出力も全位置の列である。注意機構があるので、位置 $p$ の入力は位置 $q \ne p$ の出力にも影響する。ヤコビアンを正確に書くと位置の対ごとに $d \times d$ のブロックがある。

### 6.1 位置対ごとのブロック

$$
J_\ell^{(p \to q)} = \frac{\partial h_{L,q}}{\partial h_{\ell,p}} \qquad (d \times d)
$$

「層 $\ell$ の位置 $p$ を動かすと、最終層の位置 $q$ がどう動くか」。全体のヤコビアンはこれを $(q, p)$ に並べた巨大な行列である。

### 6.2 因果性でゼロになるブロック

§3.5 より、モーション位置では $q < p$ のとき位置 $q$ の出力は位置 $p$ の入力に依存しない。したがって

$$
J_\ell^{(p \to q)} = 0 \quad (q < p,\ \text{モーション位置同士})
$$

テキスト位置は双方向なので、テキスト同士ではこの性質が無い。またモーション位置からテキスト位置への影響もゼロである（テキストはモーションを見ない）。

### 6.3 1 枚の $J_\ell$ にまとめる

J-Lens が 1 枚の $d \times d$ 行列として $J_\ell$ を定義するために、**どの位置対を集めるか**を決める。ソース位置の集合を $S$、ターゲット位置の集合を $T$ とし、

$$
J_\ell = \mathbb{E}_{\text{例}}\ \mathbb{E}_{p \in S}\ \sum_{q \in T} J_\ell^{(p \to q)}
$$

とする。ソースについては**平均**、ターゲットについては**和**を取る。「位置 $p$ の状態が、ターゲット位置全体の出力に与える影響の総和」を、ソース位置と例で平均したものである。

これが公式実装と同じ推定量で、言語モデル版との違いは $S$ と $T$ の選び方だけである。

### 6.4 `motion` モード（M-lens）

$S = T = $ モーション位置（最後の位置は除く。その位置の正解が与えたコードの外にあるため）。

読み出し $\mathrm{lens}_\ell(h_{\ell,p})$ の意味: 「位置 $p$ の状態は、$p$ 以降のモーション出力をどのコードの方向に押しているか」。§6.2 より和に効くのは $q \ge p$ だけなので、現在と将来の位置の影響が混ざった量になる。**何ステップ先かはこの段階では区別されない**。これが §8 の offset モードの動機である。

### 6.5 `text_to_motion` モード

$S = $ テキスト位置、$T = $ モーション位置。

読み出しの意味: 「テキスト位置 $p$（ある単語）の状態は、これから生成されるモーションをどのコードの方向に押しているか」。言語モデル版の「この単語の位置で次に何が来るか」の、このモデルにおける対応物である（テキスト位置には「次の単語」の予測は存在しないため、問いを「引き起こす動き」に置き換える）。

テキスト内は双方向注意なので、ある単語の位置の状態には同じ層で他の単語の情報も混ざる。単語固有の効果を見るには、1 語だけ違う最小ペア（runs / walks）の差を取る。

### 6.6 テキスト位置をターゲットにしない理由

2 つある。(1) テキスト位置の出力は学習されておらず、読み出す意味が無い。(2) 推定量の「ターゲットの和」は因果構造（$q \ge p$ 以外はゼロ）を前提に設計されており、双方向のブロックを混ぜると意味が変わる。

### 6.7 推定量 ―― 逆伝播で行を取り出す

$J_\ell$ の第 $i$ 行は、出力成分 $i$（最終層の第 $i$ 次元）の勾配である。これは自動微分でそのまま得られる。

1. 系列を 1 回 forward し、層 $\ell$ と最終層の活性を記録しておく。
2. 最終層の活性に対して「ターゲット位置 $q \in T$ すべてで第 $i$ 成分だけ 1、他は 0」というベクトル（one-hot の cotangent）を与えて逆伝播する。
3. 層 $\ell$ の位置 $p$ に返ってくる勾配は $\sum_{q \in T} \partial h_{L,q,i} / \partial h_{\ell,p}$、すなわち $\sum_q J_\ell^{(p \to q)}$ の第 $i$ 行である。
4. それを $p \in S$ で平均して、$J_\ell$ の第 $i$ 行とする。
5. $i = 1 \ldots d$ で繰り返す。$d = 3200$ 回の逆伝播が必要だが、同じ入力を `dim_batch` 本複製して各複製に別の $i$ を割り当てれば、1 回の逆伝播で `dim_batch` 行取れる。`dim_batch = 8` なら 400 回。
6. 1 回の forward から全ソース層の勾配が同時に取れるので、全 24 層分の $J_\ell$ が 1 例あたり 400 回の逆伝播で揃う。

計測では 3B で 1 例あたり 40〜63 秒（系列長に依存）、1000 例で約 14 時間。

> コード: `jlens_motion/fitting.py` の `jacobian_for_example`（1 例分）、`fit`（例の平均、チェックポイント）、`motion_to_motion` / `text_to_motion`（$S, T$ の定義）。`hooks.py` の `ActivationRecorder` が活性の記録。

### 6.8 motion と text_to_motion の違い、どちらが要るか

違いは「どの位置の残差を読むか」だけだが、答えられる問いが異なる。

| | motion | text_to_motion |
|---|---|---|
| 読む残差（ソース $S$） | モーション位置 $c_i$ の状態 | テキスト位置（単語）の状態 |
| 影響先（ターゲット $T$） | それ以降のモーション出力 | モーション出力 |
| 読み出しの意味 | 「$c_i$ まで見た時点で、次に何を出そうとしているか」 | 「この単語の位置の状態は、生成される動きをどちらへ押しているか」 |
| 答える問い | どの層で動きが決まるか、何ステップ先まで持っているか | テキストが何を引き起こすか、どの単語が効くか |
| 介入の場所 | 生成中のモーション位置 | プロンプトのテキスト位置 |

テキスト位置は双方向で次トークン予測の学習が入っておらず、モーション位置は因果で予測が学習されている。以降の層の変換の仕方が両者で違うので、平均ヤコビアンは別物になり、片方を他方に流用できない。

**motion モードが必要な理由**

1. **J-Lens が効くかの検証は motion モードでしかできない。** 「読み出しが最終出力と一致するか」を測るには、最終出力が学習されている位置で読む必要がある。テキスト位置の出力は最後の 1 つを除いて学習されていないので比較対象が無い。motion モードは全体の基準線である。
2. **「どの層で決まるか」「何ステップ先か」はモーション位置の話。** 生成はモーション位置で 1 コードずつ進む。offset モードも motion モードの派生。
3. **生成中の介入はモーション位置に掛ける。** 方向 $v_c = J_\ell^\top W_U[c]$ は motion モードの $J_\ell$ から作る。

**text_to_motion の役割**: 「テキストとモーションの関係」に直接答える追加の 1 本。runs/walks の最小ペア、言い換えの効果、単語位置への介入はこちらを使う。motion モードの結果（J-Lens が効く層があるか）を見てから fit すれば無駄がない。

**ヤコビアンは実験ごとに作り直さない**: $J_\ell$ はモデルの一般的な性質として一般のキャプションで 1 回 fit し、どのプロンプトにも使い回す（論文も 1 本の lens を全プロンプトに共通で使う）。runs/walks 用に作り直す必要はない。作るのはモードごと（motion、text_to_motion、offset）に 1 回ずつで、モデル（3B/7B、train 版/all 版）が変われば別に fit する。例外は、見たいプロンプトが fit の分布から大きく外れる場合（1 語だけの入力など）で、そのときは分布を合わせた fit と読み出しが変わらないかを確認する。

**1000 例で足りるか**: fit で平均しているのは $d \times d$ の方向対応であり、「どのコードを見たか」は入っていない。必要なのは残差の状態の網羅で、1000 例 × 50〜100 位置あれば十分（公式の経験則は 100 例で実用、1000 例で飽和）。収束は `rel_change` で監視する。語彙が平ら（val だけで 64,000 中 60,906 コードが出現、上位 10,000 コードでトークンの 53%）であることが効くのは評価側で、コード単位の集計は 1 コードあたりの位置数が少なすぎて信頼できない。6 軸座標やコード群で集計する。

## 7. 読み出しから「動き」へ

### 7.1 読み出しはコードの確率分布

$\mathrm{lens}_\ell(h_{\ell,p})$ は 64,001 次元のベクトル（logit）で、softmax を取れば「位置 $p$ の次のコードは何か」の確率分布になる。モデル本来の出力 $W_U\,\mathrm{norm}(h_{L,p})$ も同じ形の分布なので、同じ土俵で比べられる。

### 7.2 コードは 6 つの数字でもある

（コードと FSQ の仕組みは §2.3 を参照。）FSQ では、6 次元の連続ベクトルを各軸で有限個の値に丸める。本モデルの格子は $[8, 8, 8, 5, 5, 5]$、つまり 6 軸で、各軸がそれぞれ 8, 8, 8, 5, 5, 5 段階の値を取る。格子点の総数が $8 \cdot 8 \cdot 8 \cdot 5 \cdot 5 \cdot 5 = 64{,}000$ で、コード番号はこの格子点の通し番号である。

したがって任意のコード $c$ は 6 つの整数座標 $(a_1, \ldots, a_6)$ に戻せる。コードの確率分布が与えられれば、各軸の期待座標 $\mathbb{E}[a_k]$ を計算して、64,000 次元の分布を 6 次元に要約できる。「層 $\ell$ はどの軸をどちらへ動かそうとしているか」という読み方である。軸そのものに意味ラベルは付いていないので、意味は次のデコードで付ける。

### 7.3 デコーダで 272 次元へ、そして関節へ

FSQ のデコーダは、コード列（各コードを 6 次元の格子座標に戻した列）を受け取り、272 次元 × 2N フレームの動きを出す。272 次元にはルートの速度・向きの変化・関節の位置・関節の回転・速度が入っており（内訳は §1.2）、ここからルートの軌跡と各関節の回転を復元し、SMPL-X を通して 22 関節の位置にすれば動画になる。推論経路（`inference_batch.py`）がそのまま使える。

つまり**どんなコードの分布も、argmax を取れば 2 フレームの動きになる**。これが「読み出しを動きとして見られる」理由である。

### 7.4 読み出し列をデコードするときの注意

- 読み出しは位置ごとに「次の 1 コード」の予測である。位置 $p$ の読み出しを全 $p$ で並べれば、最終出力と同じ長さのコード列になる。
- ただし各位置の予測は、**正解の前置き**を文脈にした 1 ステップ予測である（teacher forcing）。層 $\ell$ が単独で先まで生成した列ではない。
- デコーダは畳み込みで前後のコードも見るので、1 コードだけ差し替えて 2 フレームだけ見る、という切り出しは正確ではない。列として比べる。
- 「層 $\ell$ はどの動きか」を単独で問うより、「最終出力と比べてどの位置・どの軸がまだ違うか」を見るほうが解釈しやすい。

### 7.5 最終出力との一致の測り方

層 $\ell$ の読み出しが信用できるかを、最終出力との一致で測る。

- **順位**: 最終出力の argmax コードが、層 $\ell$ の読み出し分布で何位にいるか。全モーション位置で平均。
- **KL**: 最終出力の分布と読み出し分布の KL ダイバージェンス。
- **top-1 一致率**: argmax 同士が一致した位置の割合。

これを層 $\ell = 1 \ldots L$ で並べ、logit lens と J-Lens を重ねる。J-Lens が logit lens より良ければ「浅い層も読める」、同程度なら「非言語の自己回帰モデルでは J-Lens の利点が出ない」。どちらも結果である（`docs/07` の検証 1・2）。

> コード: `lens_readout` が `(lens_logits[l], model_logits)` を返す。集計スクリプトは未実装。

## 8. offset モード ―― 「何ステップ先まで決めているか」を測る

### 8.1 問題: 平均は時間を潰す

§6.4 の `motion` モードでは、$J_\ell = \mathbb{E}_p \sum_{q \ge p} J_\ell^{(p \to q)}$ と、位置 $p$ から**すべての将来位置**への影響を足し合わせている。読み出しには「次のコード」への影響も「8 ステップ先のコード」への影響も混ざっており、分けられない。

知りたいのは「層 $\ell$ の位置 $p$ の状態は、何ステップ先の出力まで決めているか」である。そのためには $q - p$ ごとに分けて平均すればよい。

### 8.2 定義

オフセット $\Delta = q - p \ge 0$ ごとに、

$$
J_\ell^{(\Delta)} = \mathbb{E}_{\text{例}}\ \mathbb{E}_{p}\left[\frac{\partial h_{L,\,p+\Delta}}{\partial h_{\ell,\,p}}\right]
$$

と定義する。$\Delta$ ごとに $d \times d$ の行列が 1 枚ずつできる。`motion` モードの $J_\ell$ は、これを $\Delta$ について足したものに等しい。

読み出しは

$$
\mathrm{lens}_\ell^{(\Delta)}(h_{\ell,p}) = W_U\,\mathrm{norm}\!\left(J_\ell^{(\Delta)} h_{\ell,p}\right)
$$

で、意味は「位置 $p$ の層 $\ell$ の状態は、位置 $p + \Delta$ の出力をどのコードの方向に押しているか」。位置 $p + \Delta$ の出力はコード $c_{i + \Delta + 1}$（$p = L_t + i$ のとき）を当てるものなので、**$\Delta = 0$ が通常の次コード予測、$\Delta = 4$ なら 5 コード先（約 0.33 秒先）の予測**にあたる。

### 8.3 なぜ正しいと言えるか

- $J_\ell^{(\Delta)}$ は定義通り、「位置 $p$ の状態の微小変化が、位置 $p+\Delta$ の最終残差に与える一次の影響」の平均である。§5 の J-Lens が「以降の層を線形で代用する」ことの妥当性に依拠しているのと全く同じ意味で、offset 版は「位置 $p$ から位置 $p+\Delta$ への経路（以降の層の注意を通る）を線形で代用する」。新しい仮定は増えていない。
- 一次近似と平均という 2 つの近似の妥当性は、`motion` モードと同じく、**読み出しが実際の出力と一致するかで実証的に確かめる**。$\Delta$ ごとに、位置 $p+\Delta$ の最終出力（または正解コード $c_{i+\Delta+1}$）が読み出し分布で何位か、top-1 一致率はいくつかを測る。
- 理屈の上での保証（微分の定義と連鎖律）と、経験的な検証（一致率）の両方が揃って初めて「層 $\ell$ は $\Delta$ ステップ先を持っている」と言える。

### 8.4 なぜ 1 回の逆伝播で全 $\Delta$ が得られるか

§6.7 の手順で、cotangent を「ターゲット位置 $q$ 1 つだけの第 $i$ 成分」にして逆伝播すると、層 $\ell$ の**すべての位置** $p \le q$ に勾配が返ってくる。位置 $p$ に返った勾配は $\partial h_{L,q,i} / \partial h_{\ell,p}$、すなわち $J_\ell^{(\Delta = q - p)}$ の第 $i$ 行である。

つまりターゲットを 1 つ決めて逆伝播するたびに、$\Delta = 0, 1, 2, \ldots, q - L_t$ の全オフセットの行が同時に得られる。それを $\Delta$ ごとの箱に足し込み、最後に対の数で割る。

計算量は「1 例あたりのターゲット数 × $\lceil d / \text{dim\_batch} \rceil$」回の逆伝播。全ターゲットを使うと高いので、1 例から数個の $q$ をランダムに選ぶ（`--targets-per-example 4`）。メモリは「層数 × オフセット数 × $d^2$」なので、層を数個に絞る（`--layers 6,12,18`）。

### 8.5 結果の読み方と、必ず置くべきベースライン

横軸 $\Delta$、縦軸に一致率（または順位）を取ると、右下がりの**減衰曲線**になる。$\Delta = 0$ で高く、どこかで偶然当たる水準まで落ちる。落ちる位置が「その層が持っている計画の幅」である。層ごとに曲線を重ねれば、深い層ほど幅が広いか、特定の層で急に広がるか、が見える。

ただし次の点に注意する。

- **動きは滑らかである**。隣り合うコードは似ているので、「$c_i$ を知っていれば $c_{i+5}$ もだいたい当たる」ことがある。これは「層が先を計画している」のではなく「動きが連続的だ」というだけの話である。
- したがって必ず**ベースライン**を置く。例えば「$c_i$ をそのまま $c_{i+\Delta+1}$ の予測とする」（コピー基準）、「$c_i$ から $c_{i+\Delta+1}$ への遷移頻度」（n-gram 基準）。読み出しの一致率がこれらを上回る分だけが、内部状態が持っている「先の情報」である。
- 曲線の落ち方が層によって違うことが本題である。全層で同じならモデルの計画性ではなく動きの滑らかさを見ているだけになる。

### 8.6 何が分かるか

- 層ごとの計画の幅。「踏み切りの時点で着地まで決まっているか」のような問いに、数値で答えられる。
- 静的な動きしか出ない、という生成の弱さが「先を持てていない」ことに由来するのかを、機構側から説明できる。
- 論文に無い独自の拡張（`docs/07` の検証 3）。

> コード: `jlens_motion/fitting.py` の `offset_jacobians_for_example`（1 例分）、`fit_offsets`（平均）、`jlens_motion/lens.py` の `OffsetJacobians.mean(layer, offset)` と `transport`。`fit_jlens.py --mode offset --layers ... --offsets ...`。

## 9. 介入 ―― 読み出しの方向に沿って残差を動かす

### 9.1 方向 $v_c$ の導出

J-Lens 付きモデルで、コード $c$ の logit は（$\mathrm{norm}$ を無視すれば）

$$
\mathrm{logit}_c = W_U[c] \cdot (J_\ell\, h_{\ell,p}) = \left(J_\ell^{\top} W_U[c]\right) \cdot h_{\ell,p}
$$

と書ける。したがって $h_{\ell,p}$ に対する勾配、つまり「コード $c$ の点数を最も効率よく上げる残差方向」は

$$
v_c = J_\ell^{\top} W_U[c]
$$

である。これは行列 $W_U J_\ell$ の第 $c$ 行であり、公式論文の「J-lens ベクトル」そのものである。$J_\ell = I$ とすれば logit lens の方向 $W_U[c]$ になる。論文の主張の一つは、介入には $W_U[c]$ より $v_c$ のほうが効く、というものである。

### 9.2 足す・引く・入れ替える

- 押す: $h_{\ell,p} \leftarrow h_{\ell,p} + \alpha\, v_c$
- 抑える: $\alpha < 0$、あるいは方向への射影を消す $h \leftarrow h - (h \cdot \hat v_c)\,\hat v_c$
- 入れ替える: $h \leftarrow h - \alpha\, v_A + \alpha\, v_B$（論文の swap）

本モデルでは 1 コードが 2 フレームなので、「跳躍」のような動きは**コードの集合**として方向を作る。跳躍クリップに頻出するコード群の $v_c$ の平均、参照モーションを符号化したコード列の平均、あるいは FSQ の特定の軸を上げる方向、などである。

### 9.3 どこに、いつ掛けるか

- **層**: 単一の層ではなく、読み出しが最終出力と一致し始める層から数層の**帯域**にまとめて掛ける（論文も帯域を使う）。
- **位置**: モーション位置すべて。
- **タイミング**: 生成は自己回帰なので、層にフックを置いて forward のたびに適用する。すると新しく生成された位置にも毎ステップ同じ介入が掛かる。論文の「全トークン位置に適用」をそのまま自己回帰に当てはめた形である。1 位置に 1 回だけ足しても次の位置で元に戻る。
- **強さ**: $\alpha$ は小さい値から上げる。線形近似なので大きすぎると崩れる。

### 9.4 確かめ方

介入後の生成を、読み出し（期待通りの方向に動いたか）、FSQ の 6 軸座標、物理量（腰の高さ、進行速度、回転量）、そして動画で確認する。読み出しが相関であるのに対し、介入で生成が変われば因果が言える（`docs/07` の検証 5）。

> コード: 介入フックは未実装。`jlens_motion/hooks.py` の `ActivationRecorder`（記録）を「書き換え」に拡張する。公式リポジトリにも介入コードは含まれていない。

## 10. 実験の順番と、それぞれの「失敗の形」

| 順 | 実験 | 使うもの | 成功の形 | 失敗の形 |
|---|---|---|---|---|
| 1 | logit lens の層別一致率 | 重みのみ | 後半の層で一致、浅い層で不一致 | 全層で不一致なら残差ストリームの前提自体が怪しい |
| 2 | J-Lens（motion）の層別一致率 | `motion` の $J_\ell$ | 浅い層で logit lens より改善 | 改善なし。GPT-2 での報告と同様で、それ自体が結果 |
| 3 | 層ごとの読み出しのデコード | 2 の $J_\ell$ | 部位・属性ごとに決まる層が違う | 一致しない層のデコードは無意味なので 2 の後にやる |
| 4 | offset の減衰曲線 | `offset` の $J_\ell^{(\Delta)}$ | 層によって幅が違い、ベースラインを上回る | 全層で同じ曲線なら動きの滑らかさを見ているだけ |
| 5 | text_to_motion と最小ペア | `text_to_motion` の $J_\ell$ | 動詞・副詞で動く軸が違う | 差が出なければテキストの効果は少数の方向に圧縮されていない |
| 6 | 介入 | 8 の $v_c$ | 生成が期待方向に変わり、動画で確認できる | 変わらなければ読み出し方向は因果を持たない |

### 10.1 text_to_motion が効かなかった場合 ―― 研究が無意味になるか

ならない。ただし text_to_motion の読み出しが効くことに成否を賭けない設計にする。

**効かない可能性は最初から高い。** テキスト位置には unembedding が無く、次トークン予測の学習も無い（`docs/06` B1、`docs/07` では検証 4 は「余力があれば」）。研究の中核は検証 2（J-Lens は非言語の自己回帰モデルで効くか）と検証 3（計画の幅）で、text_to_motion は追加の試みである。効かなければ「テキスト位置に unembedding が無いモデルでは J-Lens の直接適用は成立しない」という適用範囲の知見になる。

**テキストとモーションの関係は motion モードだけでも見られる。**

- **最小ペアをモーション位置で比べる。** runs と walks の文で同じコード列を続けて入力し、モーション位置の各層の読み出し（motion モード）を比べる。文が違えば同じコード位置でも残差が違い、読み出しが変わる。その差が「runs が引き起こした違い」で、どの層で差が生まれるかも分かる。テキスト位置を読まずにテキストの効果を測る方法。
- **最後のテキスト位置。** ここだけは $c_0$ を予測するよう学習されているので比較対象がある。「プロンプトを読み終えた時点で最初に何を出そうとしているか」は層ごとに正当に読める。
- **活性パッチング。** runs の文を通したときのテキスト位置の残差を、walks の文の同じ層・同じ位置に差し替え、モーション出力がどれだけ runs 側に動くかを層ごとに測る。ヤコビアンは不要で、因果が直接言える。J-Lens の読み出しが効くかとは独立に成立する。
- **モーション位置への介入をテキスト条件で比べる。** motion モードの $v_c$ で同じ介入をしたとき、テキストによって効き方が変わるかを見る。

**主張を一本に賭けない構成。**

1. motion モードで J-Lens が logit lens より読めるか（効いても効かなくても結果）。
2. 効いた層で、動きがどの層で決まり、何ステップ先まで持っているか（独自拡張）。
3. テキストの効果を、最小ペアのモーション位置比較と活性パッチングで示す（text_to_motion に依存しない）。
4. text_to_motion の読み出しを試し、効けば 3 を補強、効かなければ適用限界として報告。

**本当に無意味になる場合。** 1 で全層において J-Lens が logit lens と変わらず、かつ logit lens も後半の層以外で読めないなら、「層ごとの読み出し」という枠組み自体がこのモデルに向いていない。その場合でも 3 の活性パッチングは生きるが、J-Lens を使う意義は薄れる。これは 1000 例の fit と一致率の集計で最初に分かるので、そこで方針を決める。

## 11. よくある疑問（Q&A）

本文を読んだ後に実際に出た疑問と、その答えをまとめる。各項目は本文の該当節を指すので、順に読まなくてよい。

### Q1. 「位置」とは何か

系列の中の何番目のスロットか、という意味である。Transformer は「ベクトルの列」を処理し、列の各要素に 0, 1, 2, … と番号が付いている。それが位置である。位置ごとに $d = 3200$ 次元のベクトルが 1 本あり、24 層を通る間、各位置は自分のベクトル（残差ストリーム）を持ち続ける。層の中で位置をまたぐのは注意だけで、FFN は位置ごとに独立に働く（§3.2, §3.3）。位置の順番は RoPE という位置符号化で各層の注意に伝えられる。

```
位置:    0     1       2      3        |   4     5     6
内容:   [A] [person] [runs] [forward]  |  [c_0] [c_1] [c_2]
         ↑ テキスト位置（T5 のベクトル）    ↑ モーション位置（コードの埋め込み）
```

「位置 2 の層 8 の残差」と言えば、"runs" のスロットが 8 層目まで処理された時点のベクトルを指す。

### Q2. J-Lens の図の入力 $x$ は何か。テキストは 1 本の高次ベクトルではないのか

$x$ は入力トークン列で、このモデルでは 2 種類が混ざっている。

| 位置 | $x_t$ の正体 | ベクトル化 |
|---|---|---|
| テキスト | キャプションを T5 で符号化した 2048 次元の連続ベクトル。**サブワードごとに 1 本**（最大 150 本） | 線形層 `llama_proj` で 3200 次元に |
| モーション | FSQ コード番号（0〜63,999 の整数） | 埋め込み表 `wte`（64,002 行）で 3200 次元に |

テキストは 1 本にまとめられてはいない（学習・推論の設定で `text_sum_way` は未指定）。T5 は双方向なので各ベクトルには文全体の文脈が既に混ざっているが、サブワードの数だけ位置を占める。違いは「語彙表を引いて作ったベクトル」か「T5 が計算したベクトル」かだけで、LLaMA から見ればどちらも位置ごとの 3200 次元ベクトルである（§2.1）。

### Q3. テキストを基にどうやってモーションを生成するのか

位置をまたいで情報を運ぶ部品は注意だけである。注意マスクは「テキスト位置同士は双方向、モーション位置は全テキスト位置と自分より前のモーション位置を見る」（§3.5）。生成は次のように進む。

| ステップ | 入力の列 | 予測するもの |
|---|---|---|
| 1 | [A][person][runs][forward] | 最後のテキスト位置の出力 → $c_0$ |
| 2 | [A][person][runs][forward][$c_0$] | $c_0$ の位置の出力 → $c_1$ |
| 3 | [A][person][runs][forward][$c_0$][$c_1$] | $c_1$ の位置の出力 → $c_2$ |
| … | … | END が出るまで |

最初の 1 歩だけはテキストの埋め込みしか無い。予測されたコード $c_0$ は `wte` で 3200 次元にされ、系列の末尾に新しい位置として足される。以降は「自分が生成したコードの埋め込み」も入力に含まれる。これが自己回帰で、言語モデルがプロンプトの後に自分の出した単語を付け足していくのと同じである。

「テキストを基に生成する」の実体は、**モーション位置の各層の注意が、必要なテキスト位置のベクトルを重み付きで取り込み、残差に足していく**ことである。"runs" の位置に強く注意を向ければ速い動きのコードが押され、"forward" を見れば進行方向が決まる、という積み重ねが条件付けになる。この配線自体は明らかで、分かっていないのは「どの層の注意がどのテキスト位置を読み、その情報がモーション側の残差にいつ現れるか」という途中の過程である。それを調べるのが本稿の目的である。

### Q4. 途中の層を「テキスト（単語）」で読めないのか

読めない。読み出し $\mathrm{softmax}(W_U\,\mathrm{norm}(J_\ell h_\ell))$ の $W_U$ はモデルの出力層 `lm_head` で、その 64,001 行は全部モーションコード（＋END）である。単語に対応する行は 1 つも無い。

- テキスト側: 入口（T5 → `llama_proj`）はあるが、出口が無い。
- モーション側: 入口（`wte`）も出口（`lm_head`）もある。

モデルは一度も単語を出力するよう学習されていないので、残差の中に「単語の方向」という座標系が存在する保証が無く、読み出す行列も無い。T5 の語彙を `llama_proj` の逆変換で借りる案は、`llama_proj` が 2048 → 3200 の片道の線形層で、LLaMA の内部状態が T5 の空間に戻る理由が無いため、理論的な裏付けが無い（`docs/06` B1）。

「テキストの言語モデルで J-Lens をやる」という意味なら、それは原論文そのものである。このモデルを選ぶ理由は、「出力が言葉ではなく動きであるモデルで、同じ層ごとの読み出しが成り立つか」が未検証の問いだからである。

### Q5. 全部の系列を一度に入れて、何が分かるのか（teacher forcing の意味）

モーション位置は因果マスクなので、位置 $t$ の状態は $t$ 以前しか見ない。したがって 30 個のコード列を一度に入れたときの位置 10 の状態は、「生成を 10 個目まで進めた時点の状態」と完全に同じである。全部入れるのは、30 回の生成ステップを 1 回の forward でまとめて計算する手抜きに過ぎず、生成そのものを再現している。

最終層は各位置で次のコードを予測する。例えば「蹴る」動きのコード列なら

| 位置 $t$ | 見ているもの | 最終層の予測 |
|---|---|---|
| 5 | $c_1 \ldots c_5$（立っている） | $c_6$（まだ立っている） |
| 10 | $c_1 \ldots c_{10}$（重心が動き始める） | $c_{11}$（脚が上がり始める） |
| 15 | $c_1 \ldots c_{15}$ | $c_{16}$（蹴り出し） |

ここまでは普通の推論と同じで新しい情報は無い。J-Lens は**同じ位置の途中の層に、同じ質問をする**。

| 位置 $t$ | 層 8 の読み出し | 層 16 の読み出し | 最終層 |
|---|---|---|---|
| 5 | 立っている | 立っている | 立っている |
| 10 | 立っている | 脚が上がる | 脚が上がる |
| 15 | 立っている | 蹴り出し | 蹴り出し |

この表から「脚を上げる決定は層 8 には無く層 16 にはある、つまり層 8〜16 のどこかで形成される」と読める。最終層の出力だけでは決定が「いつ」「どこで」できたかは分からない。それを層の軸に沿って見るのがレンズの目的である。

「列として扱う」とは、上の表の「層 8 の列」を縦に読んで 1 本のコード列と見なし、まとめて FSQ デコーダに通すことである。最終層の動画は蹴っているのに層 8 の動画は立ったままなら、浅い層はまだ「静止の継続」しか持っておらず、蹴りの計画は深い層で生まれる、と目で確認できる（§7.4）。

1000 例 × 全位置で「層 $\ell$ の読み出しが最終層の答えと一致した割合」を集計すると層ごとの 1 本の曲線になる。浅い層から高ければ動きは早く決まっている、深い層で急に上がれば決定は後半に集中している、logit lens の曲線より上なら J-Lens がこのモデルで有効、と読む。これが研究の第一の問いである。

### Q6. モーションコード 1 個を見ても何も分からないのでは

その通りで、コード 1 個は 2 フレーム（1/15 秒）の断片であり、番号を見ても「蹴り」のような動作単位にはならない。しかし読むのは最後の 1 位置だけではない。Q5 の通り全位置で同時に読み出し、列として扱うので、次の 3 つの方法で意味を取り出せる。

- **列としてデコードする。** 層 $\ell$ の読み出し列をまとめて FSQ デコーダに通し、数秒分の動きとして見る。デコーダは畳み込みで前後のコードも見るので、1 個だけ切り出す評価は正確でなく、数コードの窓で評価する（§7.4）。
- **コード番号ではなく 6 軸座標で集計する。** コードは FSQ の 6 次元格子の点なので、読み出し分布を 6 軸に射影できる（§7.2）。
- **最終出力との一致率・KL を集計する。** コードの意味を解釈しなくても成立する（§7.5）。

残る本当の制約は、teacher forcing の読み出しが「正解の前置きを見たうえでの 1 ステップ予測」であり、層 $\ell$ が単独で先まで生成した列ではないことである。「層 $\ell$ がどんな動きを考えているか」を単独で問うより、「最終出力と比べてどの位置・どの軸がまだ違うか」を問うほうが正当である。

### Q7. 新しい任意のモーションやプロンプトには使えないのか

使える。前提は 2 つだけである。

- **$J_\ell$ は入力に依存しない。** 1000 例で fit した $J_\ell$ は「層 $\ell$ 以降の変換の平均的な一次近似」で、モデルの性質として 1 回作れば、どんなプロンプト・モーションにもそのまま使う（§6.8）。
- **評価に必要なのは「モデルに通す系列」だけで、正解データではない。** 比較対象はデータセットの正解コードではなく、モデル自身の最終層の出力である。

したがって、新しいプロンプトなら「普通に生成してコード列を得る → テキストとその生成列を一度に入れて全位置・全層の読み出しを取り、最終層と比べる」、新しいモーションクリップ（`.npy`）なら「FSQ エンコーダでコード列にしてから入れる」で扱える。生成列を使えば「モデルが実際にした決定が各層でいつ形成されたか」、外部クリップを使えば「その文脈を与えたときの各層の傾向」になり、問いが少し違う。fit の分布から大きく外れる入力（1 語だけのプロンプトなど）では近似精度が落ちる可能性がある。

### Q8. 「立っている」「脚が上がっている」はどうやって分かるのか

コード番号にそうした意味は付いていない。Q5 の表の言葉は説明用で、実際には**コードを動きに戻してから運動学量を測る**。

1. **デコードして動画にする（目視）。** コード列 → FSQ デコーダ → 272 次元 → 関節位置 → SMPL-X 描画。`inference_batch.py` がそのまま使える。補助であり、主張の根拠にはしない。
2. **関節位置から数値を取る（自動）。** デコード後の 272 次元には 22 関節の位置と速度が入っている（§1.2）。

| 知りたいこと | 使う量 |
|---|---|
| 立っているか、動いているか | 関節速度の平均（74〜139 列）、ルートの水平速度（0〜1 列） |
| 脚が上がっているか | 足首・足先（関節 7, 8, 10, 11）の高さ y が、立位時よりどれだけ高いか |
| 腕を振っているか | 手首（関節 20, 21）の速度 |

3. **コード番号の辞書を作る（準備としておすすめ）。** val 全体で各コードが現れた 2 フレームの運動学量を平均すれば、「コード 12345 は典型的に足先の高さ 0.3 m、ルート速度 0.1 m/s」という対応表ができる。val だけで 64,000 中 60,906 コードが出現するので、ほぼ全コードに値が付く。これがあれば、読み出し分布をデコードせずに「この層の読み出しは足先が高いコードに寄っている」と即座に言える。6 軸座標との対応を見れば「どの軸が足の高さに効くか」も分かる。

なお、J-Lens が効くかの第一の評価（一致率、KL）はコードの意味を解釈せずに済む。意味付けが要るのは、効いた後に「どの層で何が決まるか」を説明する段階である。

### Q9. M-lens では「次のコード」しか分からず、text_to_motion は効かないなら、何も分からないのでは

半分は正しい。text_to_motion の読み出しは効かない可能性が高く（Q4、§10.1）、motion モードの読み出しの中身は「次のコードの分布」である。最終層でそれを読んでもモデルの出力そのもので新しくない。

誤解の部分は、「次のコード」を読む場所が最終層ではなく**途中の層**であることに意味がある点である。出力は 1 つでも、途中の 24 層それぞれに状態がある。出力は既に分かっていても、**それがネットワークのどこで、いつ決まったか**は出力からは分からない（Q5）。得られるのは「決定が深い層に集中しているか」「浅い層は静止の継続に偏っているか」「層 $\ell$ の状態が何ステップ先まで決めているか（§8）」といった、計画の形成に関する事実である。

テキストの効果は text_to_motion に頼らなくても測れる（§10.1）。

- **最小ペアをモーション位置で比べる。** runs と walks の文に同じコード列を続けて入力し、同じコード位置の各層の読み出しを比べる。差が出た層が「テキストの違いがモーション側に反映される層」である。
- **最後のテキスト位置。** ここだけは $c_0$ を予測するよう学習されているので、「プロンプトを読み終えた時点で何を出そうとしているか」を層ごとに正当に読める。
- **活性パッチング（Q10）。** ヤコビアン不要で因果が直接言える。

本当に何も分からないのは、J-Lens が全層で logit lens と変わらず、かつ logit lens も最後の数層以外で読めない場合である。GPT-2 の追試ではそうなった。その場合でも活性パッチングは生きるが、J-Lens を使う意義は薄れる。これは fit 結果の一致率の集計で最初に判明するので、評価スクリプトを書いて結果を見てから方針を決める。

### Q10. 活性パッチングとは何か

「ある位置・ある層の状態だけを別の入力のものに差し替えて、出力がどれだけ変わるかを測る」手法である。J-Lens とは独立で、読み出しの近似を使わない。

1. **1 語だけ違うプロンプトの対を用意する。** A: "A person **runs** forward"、B: "A person **walks** forward"。両方を通し、全層・全位置の残差を記録する。
2. **差し替えて走らせる。** B を入力にするが、層 $\ell$ の「walks の位置」の残差だけを A の「runs の位置」の残差に置き換え、層 $\ell$ より上はそのまま計算してモーションを生成する。
3. **出力が A 側にどれだけ寄ったかを測る。** 生成した動きのルート速度、または A が生成したコード列に B＋差し替えのモデルが付ける対数確率。無介入の B を 0、A そのものを 1 として 0〜1 の数値にする。
4. **層と位置を変えて繰り返す。**

| 差し替えた層 $\ell$ | 効果（仮の値） |
|---|---|
| 2 | 0.9 |
| 8 | 0.6 |
| 16 | 0.1 |
| 22 | 0.0 |

こうした表から「runs の情報は層 2 ではその単語の位置に局在しているが、層 16 ではもう他の位置に移っていて、1 位置を差し替えても効かない」と読める。テキスト内は双方向注意なので、単語の情報は層を上がるにつれて他のテキスト位置へ広がる。位置を変えて差し替えれば（最後のテキスト位置、テキスト全体、モーション側の位置）、**どの層で、どの位置を経由して**単語の情報がモーション生成に届くかが追える。

読み出しや SAE は「この層にこういう情報がある」という相関しか示さないが、パッチングは状態を実際に書き換えて出力の変化を観測するので、介入の意味で因果が言える。注意点として、T5 の段階で単語は既に文脈と混ざっているので、扱っているのは「単語そのもの」ではなく「その語によって変わった状態」である。対のトークン数が揃っていないと位置の対応がずれるので、同じサブワード数になる対を選ぶ。計算は forward だけで安く、fit 済みのヤコビアンも不要である。

### Q11. 右手の成分を左手に変えるような介入はできるのか

原理的にはできるが、「右手成分」という座標がコード空間に最初から存在するわけではないので、方向を自分で作る必要がある。介入の仕組みは §9 の通り $h_{\ell,t} \leftarrow h_{\ell,t} + \alpha v$ で、J-Lens からはコード $c$ を押す方向 $v_c = J_\ell^\top W_U[c]$ が得られる。「右手を左手に」なら $v = v_{c_L} - v_{c_R}$ の swap になる。

方向の作り方は 3 つある。

1. **鏡像ペアから活性差を取る（最も素直）。** ある動きとその左右反転版をそれぞれコード化してモデルに通し、層 $\ell$ の残差の差を多数の動きで平均する。ヤコビアン不要で、原論文の最小ペア steering と同じ考え方。左右反転は 272 次元で関節の添字を入れ替えて x を反転すれば作れる。データセットの Mirror_ 版は同じものだが、手元に `.npy` が無いので自作が要る。
2. **コード辞書から作る（Q8）。** 「右手首が高いコード群」と「左手首が高いコード群」の $v_c$ の平均の差を方向にする。
3. **テキスト側で差し替える。** "raises right hand" と "raises left hand" のテキスト位置の残差を入れ替えて生成する（Q10）。

確かめ方は、介入後の動きをデコードし、左手首が動くようになったか（効果）、他の部位は変わっていないか（選択性）、$\alpha$ に対して効果が単調か（用量反応）、ランダムな方向の対照と差があるか、を運動学量で測る。全身を 1 つの番号にしている以上「右手だけ」を完全に分離できる保証は無く、方向が腕以外も動かすなら、それ自体が「このモデルは左右を独立に表現しているか」という結果になる。鏡像は全身の左右反転なので、1 の方向は「全身の左右」であり、右手だけに限定するなら 2 でペアの作り方を絞る。

### Q12. 結局、この方法で大したことはできないのではないか

原論文の「言葉で中身が読める」という派手さは、このモデルでは出ない。理由はテキスト側に語彙が無いことで、最初から分かっていた。

できないこと: 内部を単語で読む。1 コードに意味付けする。部位単位の操作をきれいに切り出せる保証。

できること（言語モデルより有利な点）: 読み出しを動画と運動学量にして人手の意味付けなしに検証できる。介入の効果が数値で見える。テキストと動きが位置で分離しているので、テキストの効果を活性パッチングで層ごとに測れる（J-Lens の成否と無関係に成立）。

論文として言える主張の候補:

1. 非言語の自己回帰モデルで J-Lens は logit lens に勝つか。効いても効かなくても結果で、原論文の著者自身が「行動が言葉でないモデルで何が起きるか」を未検証の問いとして挙げている。
2. 動きの決定はどの層で形成され、何ステップ先まで持っているか（§8）。原論文に無い拡張で、静的な動きを出しやすいという既知の弱さを機構側から説明できる可能性がある。
3. テキストのどの単語が、どの層を通って動きに効くか（Q10）。
4. 左右のような属性が残差空間で分離しているか（Q11）。

テキストから人体モーションを生成するモデルの内部を層ごとに解析した論文は、調べた範囲では見つかっていない（`docs/07` §1）。主張の規模は「新しい手法」ではなく「新しい対象での最初の計測」であり、修論の成果としては成立する。弱い結果になる条件は Q9 の末尾の通りで、今ある fit 結果で一致率を集計すれば数日で分かる。

### Q13. テキストの各位置がどのモーションを注視しているかが分からないのは、全テキストが最初から入っていて、テキストからモーションが見えないからか

2 つのことが混ざっているので分ける。

**「テキスト位置がモーションを注視する」という向きは存在しない。** 注意マスクは「テキスト位置はテキスト位置だけを見る（双方向）」「モーション位置はテキスト全部と自分より前のモーションを見る」である（§3.5）。テキスト位置からモーション位置への注意は常にゼロなので、「テキストの各位置がどのモーションを見ているか」は定義できない。情報の流れは一方向で、**モーション位置がテキスト位置を読みに行く**だけである。

**逆向きの「モーション位置がどの単語を見ているか」は測れる。** 各層・各ヘッドの注意重みを見れば、「$c_{10}$ を予測する位置は、層 12 のヘッド 3 で "runs" の位置に重み 0.6 を置いている」と直接観測できる（`docs/06` 手法 C）。実装上は `scaled_dot_product_attention` が重みを返さないため、そこだけ手書きに差し替える小さな改造が要る。J-Lens もヤコビアンも不要である。

**本当に難しいのは次の 2 点で、理由は別々である。**

- **単語 1 つに帰属させにくい。** 全テキストトークンが最初から入っていて双方向なので、層を上がるにつれ "runs" の情報は他のテキスト位置にも広がる。T5 の段階でも既に文脈が混ざっている。モーション位置が "forward" の位置を見ていても、そこに "runs" の情報が含まれている可能性があり、注意重みだけでは「どの単語の効果か」を言い切れない。これが最小ペアや活性パッチング（Q10）で差分として測る理由である。
- **テキスト位置の状態を「どんな動き」として読めない。** テキスト位置には出力層が無いので、「この単語の位置は今どんな動きを押しているか」を読み出す行列が無い（Q4）。text_to_motion の J-Lens が効きにくい理由はこれで、注意の向きとは無関係である。

まとめると、「全テキストが最初からある」は帰属の難しさの原因、「テキスト側に出口が無い」は読み出しの難しさの原因で、どちらも「注視が見えない」こととは別である。注視そのものはモーション → テキストの向きで普通に測れる。

### Q14. 原論文の言語モデルでも、注意を通った後の位置（例えば "is"）では、どの単語の情報を持っているか分からなくならないのか

なる。そしてそれは原論文でも同じで、J-Lens はそもそも「どこから来たか」を答える道具ではない。

言語モデルでも、"The capital of France is" の "is" の位置の残差は、数層の注意を経た時点で "capital" や "France" の情報を取り込んでいて、どの成分がどの単語由来かは混ざっている。J-Lens がその位置で読むのは「この位置の残差は今どの語彙の方向を向いているか」（例えば "Paris" が優勢）であり、**内容**を読むのであって**出所**を読むのではない。混ざること自体は問題ではなく、むしろ注意が集めた結果が読み出しに現れるのが狙いである。出所を知りたければ、注意重みや活性パッチングといった別の道具を使う。これは原論文でも本稿でも同じである。

本モデルとの違いは、混ざった後の状態を**読めるかどうか**にある。

| | 言語モデル（原論文） | 本モデル |
|---|---|---|
| 因果の位置（次トークン予測が学習済み） | 全位置 | モーション位置と最後のテキスト位置 |
| 混ざった状態の読み出し | 全位置で正当（"is" の位置で "Paris" と読める） | モーション位置では正当。途中のテキスト位置は出力が学習されておらず読めない |
| 出所の特定 | 別の道具（注意重み、パッチング） | 同じ |

つまり原論文でも「"is" の位置がどの単語を注視したか」は J-Lens からは分からず、分かるのは「注視の結果その位置が何を言おうとしているか」である。本モデルではその読み出しがモーション位置でしか成立しない、というのが差である。

### Q15. なぜテキスト位置では読み出しが成立しないのか

理由は 3 つあり、いずれも学習のされ方に由来する。

**1. 途中のテキスト位置の出力は、何も当てるように学習されていない。** 損失が入るのは、モーション位置の出力と、最後のテキスト位置の出力（$c_0$ を当てる）だけである（§2.2）。"A person runs forward" の "runs" の位置の最終層の出力は、学習中に一度も採点されない。最終層のベクトルを $W_U$ に通したものが「予測」として意味を持つのは、学習でそう形作られた位置だけである。採点されない位置では、最終層の状態は「次の層に情報を渡すのに都合のよい何か」であって、語彙の方向に整列している理由が無い。そのため最終層ですら読めず、途中の層をヤコビアンで最終層に運んでも、運んだ先に意味が無い。

**2. 読み出しの正しさを確かめる比較対象が無い。** J-Lens が効いたかは「層 $\ell$ の読み出しが最終出力と一致するか」で測る（§7.5）。モーション位置では最終出力が学習済みの予測なので比較できるが、途中のテキスト位置には「正しい最終出力」が存在しない。読み出しが何かを出しても、正しいかを判定する基準が無い。

**3. テキスト内は双方向なので、推定量の前提が崩れる。** ヤコビアンの推定（§6.7）は「位置 $p$ の変化は $p$ 以降の位置にしか効かない」という因果構造を前提に、ターゲット位置の勾配を和にして取り出す。テキスト位置同士は双方向に見えるので、テキスト位置をターゲットにするとこの前提が崩れ、和の意味が変わる（§6.6）。ソースをテキスト、ターゲットをモーションにする text_to_motion モードならこの点は回避できるが、1 と 2 はそのまま残る。

**例外として最後のテキスト位置だけは読める。** この位置は $c_0$ を当てるよう学習されているので、1 と 2 の条件を満たす。「プロンプトを読み終えた時点で、各層は最初にどんな動きを出そうとしているか」は正当に読める。

まとめると、言語モデルでは全位置が次トークン予測で採点されるので、どの位置の残差も「語彙の方向」に整列する圧力を受けている。本モデルではその圧力がモーション位置と最後のテキスト位置にしか掛かっていない、というのが「テキストでは成立しない」の中身である。

## 12. 用語集

- **残差ストリーム**: 層をまたいで流れる $d$ 次元ベクトル。各層が修正量を足し込む。
- **注意**: 他の位置の情報を重み付きで取り込む部品。位置をまたぐ情報の流れはここだけ。
- **FFN**: 位置ごとの非線形変換。
- **unembedding（$W_U$, `lm_head`）**: 残差ベクトルを語彙の点数に変える行列。各行が 1 コードの方向。
- **logit lens**: 途中の層の残差をそのまま $W_U$ に通す読み出し。$J_\ell = I$ の J-Lens。fit 不要で、`lens_readout(..., lens=None)` として実装済み。J-Lens が超えるべき基準線。
- **ヤコビアン**: 多変数関数の一次近似を与える行列。ここでは「層 $\ell$ 以降の処理」の近似。
- **J-Lens ベクトル $v_c$**: $J_\ell^{\top} W_U[c]$。層 $\ell$ でコード $c$ を押す方向。
- **S / T**: ヤコビアンを集めるソース位置とターゲット位置の集合。モードの違いはここだけ。
- **offset $\Delta$**: ソース位置とターゲット位置の差。$\Delta = 0$ が通常の次コード予測。
- **teacher forcing**: 正解の系列を全部入れて各位置の予測を同時に見ること。読み出しの評価はこの設定。
- **FSQ**: 連続ベクトルを 6 軸の格子に丸める量子化。コード番号は格子点の通し番号。
- **steering / swap**: 残差に方向を足す・引く・入れ替える介入。

## 付録 A. 小さな数値例（$d = 2$）

残差が 2 次元、語彙が 2 コード $\{A, B\}$ のおもちゃを考える。

- unembedding: $W_U[A] = (1, 0)$、$W_U[B] = (0, 1)$。つまり第 1 成分が大きければ A、第 2 成分が大きければ B。
- 層 $\ell$ の残差: $h_\ell = (1, 0)$。logit lens で読むと A が勝つ。
- 以降の層が「2 成分を入れ替える」変換だったとする: $f_\ell(h) = (h_2, h_1)$。すると $h_L = (0, 1)$ で、本当の出力は B。logit lens は外れる。
- $f_\ell$ のヤコビアンは $J_\ell = \begin{pmatrix} 0 & 1 \\ 1 & 0 \end{pmatrix}$。$J_\ell h_\ell = (0, 1)$ となり、J-Lens は正しく B を読む。
- 介入: 層 $\ell$ で B を押す方向は $v_B = J_\ell^{\top} W_U[B] = (1, 0)$。「最終的に B になる方向」は、層 $\ell$ では第 1 成分だと分かる。logit lens の方向 $W_U[B] = (0, 1)$ を足しても、以降の層で入れ替えられて A を押してしまう。

実際の $f_\ell$ は非線形で入力依存だが、J-Lens は「平均的な入れ替え方」を実測して同じことをしている、と読めばよい。
