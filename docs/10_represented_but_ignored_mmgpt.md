# 「表現されているが使われていない」の検証 ―― 元論文の整理と MMGPT への応用

> 対象: MotionMillion の 3B text-to-motion LLaMA（以下 MMGPT）。
> 位置づけ: J-lens の検証（`docs/06`〜`docs/09`、feature/jlens ブランチ）で「このモデルでは平均ヤコビアンによる中間層の読み出しは logit lens に勝てず、logit lens 自体も後半 6〜8 層でしか読めない」ことが確定した（held-out val 300 例、約 21,000 位置）。本ドキュメントは、その結果を受けて主軸を「内部表現と生成行動の乖離を因果的に特定する」研究に切り替えるための設計メモである。
> 関連調査: `docs/research/text-to-motion-interpretability-survey.md`（最新 T2M モデルと内部解析研究の調査、45 ソース）。

---

## 0. 一行で

> **モデルは細粒度の指示（回数・部位・方向・速さ・順序）を内部では表現しているのに、生成では使っていないのではないか。** それを、プローブ（表現の有無）・行動測定（出力への反映）・介入（差し替えで出力が動くか）の 3 段で切り分ける。

音声 LLM で同じ問いに答えた論文（§1）の手順を、テキスト → モーションの構造に翻訳する（§2）。語彙への読み出しに依存しないので、J-lens が効かなかったことは障害にならない。

## 1. 元論文: Represented but Ignored

### 1.1 書誌

- Linkai Peng, Baorian Nuchged, "Represented but Ignored: A Causal Account of Prosodic Underuse in Audio-Language Models", arXiv:2608.19211 [cs.CL], 2026 年 6 月（プレプリント）。
- 対象: 理解専用の音声 LLM 4 種。Qwen2.5-Omni-7B（Whisper 型音声塔 + 28 層 LLM）、Phi-4-multimodal-instruct（5.6B、Conformer + 32 層）、Audio-Flamingo-3（8.3B、Whisper-large-v3 + Qwen2.5-7B）、DeSTA2.5-Audio（8.7B、Whisper-large-v3 + Llama-3.1-8B）。
- 問い: 音声 LLM は韻律（疑問のイントネーション、感情）を答えに反映しないことが多い。それは (F1) 音声経路で情報が失われているのか、(F2) 内部で誤って解釈されているのか、(F3) 内部には表現があるのに答えで使っていないのか。

### 1.2 データ設計: 内容を揃えた対比

同一話者・同一（またはほぼ同一）の語句で、韻律ラベルだけが反対の発話対を使う。IViE（疑問 / 平叙、430 対）、CREMA-D（感情 4 クラス、4,348 対）、VESUS（感情 4 クラス、held-out、10,073 対）。語彙内容を固定することで、観測される差を韻律だけに帰属させる。

### 1.3 プローブの階段（probe ladder）

3 段階で「情報がどこまで残っているか」を測る。

| 段 | 測る場所 | 手法 | 指標 | 代表値 |
|---|---|---|---|---|
| 1. 音声経路 | 音声エンコーダ各層、LLM に渡る射影出力 | 層ごとの線形分類器 | 重み付き正解率（WA） | IViE 0.71〜0.81、CREMA-D 0.79〜0.92。Phi-4 は VESUS の感情をほぼ符号化しない（≤ 0.52） |
| 2. LLM 内部 | 回答位置（生成開始直前の最終トークン）の残差、層ごと | logit lens（unembedding を各層に適用）と V-information（L2 正則化線形 softmax プローブの予測情報量、bit） | AUC、bit | IViE で AUC 0.81〜1.00（ただし V-info は 0.23〜0.41 bit、上限 1 bit）、CREMA-D で AUC 0.61〜0.99 |
| 3. 行動 | 最終回答 | 3 条件比較 | 回復率 | 下記 |

**行動の 3 条件**: ベースライン（書き起こしのみ）、テスト（書き起こし＋音声）、参照（書き起こし＋韻律を明示したテキスト手掛かり）。

$$
\text{回復率} = \frac{\text{テスト} - \text{ベースライン}}{\text{参照} - \text{ベースライン}} \times 100
$$

で、「明示的に書けば答えられる分のうち、音声から実際に回復できた割合」を測る。IViE では 0〜36%（DeSTA は 0%: 書かれない限り全部「平叙」と答える）、CREMA-D では 48〜92%。

**判定**: 段 1 で失われていれば F1、段 2 の AUC が低ければ F2、段 2 が高いのに段 3 が低ければ F3（表現されているが使われていない）。結果は 11 セル（モデル × 対比）中 7 セルが F3。

### 1.4 因果検証

- **方向注入**: プローブ方向を回答位置の残差に $\alpha$ 倍で足す。18 セル全てで傾きが正（95% 信頼区間が 0 を含まない）。15 / 18 セルで $\alpha$ を上げると再現率が飽和（例: Qwen × CREMA-D の angry 再現率 0.366 → 1.000）。
- **活性パッチング**: 反対クラスのドナー発話を lens のピーク層 $L^*$ まで走らせ、回答位置の残差を受け手に移植して続きを計算する。16 件すべてで対数オッズが予測方向に動き、方向を逆にするとほぼ反対称（例: AF3 +3.3 / −3.4）。
- **単一編集で十分**: 多くのセルで $L^*$ の 1 か所を 1 回編集するだけで、抑えられていた韻律側の判断に動く。

### 1.5 特徴レベル

- $L^*$ の活性に TopK SAE を学習し、AtP\* で回答トークンの対数オッズへの寄与で特徴を順位付け。寄与の 95% を覆う特徴集合 $S_{0.95}$ は 33〜102 個で、辞書の 0.5% 未満。
- $S_{0.95}$ の座標を陽性クラスの平均パターンへクランプすると、18 セル中 17 で陽性再現率が 1.00 に回復。
- 上位特徴と音響量の相関: 感情特徴は RMS エネルギーと $r$ = 0.49〜0.73、イントネーション特徴は F0 傾きと $|r| \approx 0.3$ と弱い。

### 1.6 著者が挙げる限界

- 介入は「選択的な回復」ではなく「極への偏向」。回復に必要な $\alpha$ では陰性クラスも境界を越える。
- 参照条件は実用上の上限であって真の上限ではない。韻律を語彙より系統的に軽視するモデルでも同じパターンになる。
- logit lens は素の版を使っており、中間層の形は通常の注意で読むべき（後半層のピークは頑健）。
- 単一残差ストリームを仮定するため、MoE 構造には適用できない。

## 2. MMGPT への対応付け

### 2.1 構造の対応

| 元論文 | MMGPT | 備考 |
|---|---|---|
| 音声エンコーダ + 射影 | flan-T5-XL エンコーダ（凍結）+ `llama_proj` | 「段 1」はここをプローブする。T5 は凍結なので入力側の表現は学習で変わっていない |
| LLM（28〜32 層、単一残差） | LLaMA 24 層、$d$ = 3200、単一残差 | SAE・lens の前提（単一残差）を満たす |
| 書き起こし（語彙内容） | プロンプトの主動作（"a person raises a hand"） | 対で固定する部分 |
| 韻律（非語彙の手掛かり） | 細粒度属性の語（left / right、three times、backward、slowly、then） | 対で変える部分。音声と違い**テキストの中にある**ので、段 1 は「T5 がその語を符号化しているか」になる |
| 回答位置（生成開始直前の最終トークン） | 最後のテキスト位置（$c_0$ を予測する位置）、およびモーション位置 | テキスト位置のうち出力が学習されているのはここだけ |
| 回答トークンの対数オッズ | 生成モーションの運動学量（§2.3） | 離散クラスの対数オッズは無いので、デコード後の連続量で測る |
| 音響量（F0、エネルギー） | 運動学量（手首の高さ、ルート速度、向きの変化、周期） | 特徴の接地先 |

MMGPT 固有の点が 2 つある。

1. **「手掛かり」がテキスト内にある。** 元論文はモダリティ間（音声 → テキスト回答）だが、ここではテキスト内の 1 語がモーションに反映されるかを問う。段 1 は T5 の語彙的符号化なので、ほぼ確実に通る。関心は段 2（LLaMA のどの層・位置まで残るか）と段 3（生成に出るか）の差になる。
2. **テキスト位置は双方向注意。** 1 語の情報は層を上がるにつれ他のテキスト位置に広がるので、パッチングは「1 位置」と「テキスト全体」の両方で行い、どちらで効くかを見る。

### 2.2 対比プロンプトの設計

T2MBench が「ほぼ全モデルのボトルネック」と報告した細粒度属性を使う。各属性で主動作を固定し、1 語（句）だけ変える。

| 属性 | 対の例 | 運動学での判定 |
|---|---|---|
| 部位 | raises the **left** hand / **right** hand | 左右手首（関節 20, 21）の変位量の比 |
| 回数 | jumps **once** / **three times** | ルート高さの極大の個数 |
| 方向 | walks **forward** / **backward** | ルート速度と向きの内積の符号 |
| 速さ | walks **slowly** / **quickly** | ルート水平速度の平均 |
| 順序 | **sits then stands** / **stands then sits** | 腰の高さの時系列の順序 |

各属性で 100〜200 対。MotionMillion-Eval と T2MBench のプロンプトを基に、属性語だけを置換して作る。サブワード数を揃え、位置の対応がずれないようにする。

### 2.3 行動の 3 条件（回復率）

| 条件 | 元論文 | MMGPT 版 |
|---|---|---|
| ベースライン | 書き起こしのみ | 属性語を抜いたプロンプト（"raises a hand"）。左右は偶然で決まる |
| テスト | 書き起こし + 音声 | 属性語を入れたプロンプト（"raises the left hand"） |
| 参照 | 書き起こし + 明示手掛かり | 属性を強調したプロンプト（"raises the left hand, not the right hand" や言い換えで 2 回言う）。実用上の上限であって真の上限ではない点は元論文と同じ |

指標は「属性が運動学量で実現された割合」。回復率は元論文と同じ式で定義する。既存の FID・R-Precision はサンプル単位で人間判断と相関しない（Voas ら）ので使わない。

### 2.4 プローブの階段（MMGPT 版）

| 段 | 測る場所 | 手法 |
|---|---|---|
| 1 | T5 出力（属性語の位置、平均）、`llama_proj` 出力 | 線形プローブ（属性 2 値） |
| 2a | LLaMA テキスト位置の残差、層 0〜23（属性語の位置、最後のテキスト位置、テキスト平均） | 線形プローブ + V-information |
| 2b | LLaMA モーション位置の残差、層 0〜23（先頭 k 位置、全位置平均） | 同上。「生成している位置まで届いているか」 |
| 3 | 生成モーション | §2.3 の実現率 |

logit lens はモーション語彙への読み出しなので属性に直接は対応しない。代替として、コード辞書（各コードが現れた 2 フレームの運動学量の平均。`docs/09` §11 Q8）で「左手が高いコード群」への確率質量を各層で読む版を補助的に置く。これは J-lens の fit 済み行列を使わない。

**判定表**

| 段 1 | 段 2a | 段 2b | 段 3 | 判定 |
|---|---|---|---|---|
| 低 | – | – | 低 | F1: 入力で符号化されていない（T5 / 射影の問題） |
| 高 | 低 | – | 低 | F2': LLaMA のテキスト処理で失われる（層 $\ell$ で消える） |
| 高 | 高 | 低 | 低 | F2'': テキストからモーション位置へ運ばれない（注意経路の問題） |
| 高 | 高 | 高 | 低 | **F3: 表現されているが使われていない** |
| 高 | 高 | 高 | 高 | 正常 |

元論文の F2 を、本モデルの構造に合わせて「テキスト内で消える」と「モーション側へ渡らない」に分けている。

### 2.5 因果検証（MMGPT 版）

- **活性パッチング**: 対の片方（left）を層 $L^*$ まで走らせ、テキスト位置の残差を他方（right）の同じ層・同じ位置に移植して生成する。移植先は (i) 属性語の位置のみ、(ii) 最後のテキスト位置のみ、(iii) テキスト位置全体、の 3 通り。実現率の変化を両方向で測り、反対称性を見る。
- **方向注入**: 段 2b のプローブ方向 $v$ をモーション位置の残差に $\alpha v$ で足して生成する。$\alpha$ に対する実現率の単調性と飽和、ランダム方向の対照、他属性（部位を変えたときに速さが変わらないか）の選択性を測る。
- **単一編集の検証**: 1 層 1 位置の編集で足りるか、複数層が要るかを層を変えて測る。

介入の効き方が「選択的回復」ではなく「極への偏向」である可能性は元論文と同じで、陰性側（right と書いたのに left になる）の割合を必ず併記する。

### 2.6 特徴レベル（余力があれば）

- $L^*$ のモーション位置残差に TopK SAE を学習する（Event-Grounded SAE と同じ設計。MusicGen・VLA で実績）。
- 特徴の寄与は、回答トークンの対数オッズの代わりに「属性に対応するコード群の確率質量」または「段 2b のプローブ出力」への AtP\* で測る。
- 上位特徴を運動学イベント（足接地の切替、手首高さの極大、ルート速度の極値）に接地する。

### 2.7 期待される結果の型

- 属性ごとの「消失点の地図」: 「回数は T5 では符号化されているが LLaMA の層 8 以降で消える」「部位は最後まで残っているのに生成は右手に偏る」のような、属性 × 層 × 位置の表。
- MotionMillion のキャプションは GPT-4o 生成で数値・順序の指示が乏しいので、「学習データに無い属性は入力で表現されていても生成側が読まない（F3）」か「テキスト側で早期に消える（F2'）」になる可能性が高い。どちらでも、改善すべき場所（データか、テキスト処理か、生成ヘッドか）を指す結果になる。
- 介入で実現率が動けば、「使えば使える情報を使っていない」ことの因果的な証拠になり、訓練なしの制御（steering）の実演にもなる。

## 3. 実装計画

### 3.1 既存資産

| 必要なもの | 既存 | 場所 |
|---|---|---|
| 系列の組み立て、forward、層別の活性記録 | あり | `jlens_motion/model.py` `MotionLensModel`、`hooks.py` `ActivationRecorder`（feature/jlens） |
| T5 符号化 | あり | `fit_jlens.py` `encode_examples` |
| コード → 272 次元 → 関節 → 動画 | あり | `models/vqvae.py` `forward_decoder`、`inference_batch.py` |
| 272 次元の内訳と運動学量の取り出し | あり | `utils/motion_process.py`、`docs/09` §1.2 |
| 生成（自己回帰） | あり | `inference_batch.py` |
| held-out 評価用のデータ | あり | `dataset/MotionMillion/all_data.pkl`（val 17,983 本） |

### 3.2 新規に書くもの

1. `prompts/attributes/*.json`: 属性別の対比プロンプト集（ベースライン / テスト / 参照の 3 条件）。
2. `kinematics.py`: 272 次元列から属性の実現を判定する関数群（左右手首変位、跳躍回数、進行方向、速度、順序）。
3. `probe_attributes.py`: 層・位置群ごとの残差を保存し、線形プローブと V-information を計算。
4. `patch_attributes.py`: 活性パッチングと方向注入を行って生成し、実現率を集計。
5. 可視化: 属性 × 層の AUC ヒートマップ、回復率の棒グラフ、介入の用量反応曲線。

### 3.3 工程と規模

| 工程 | 内容 | 計算 |
|---|---|---|
| 1 | プロンプト集と運動学判定器を作り、val の実データで判定器の妥当性を確認 | CPU |
| 2 | 3 条件で生成し、属性ごとの実現率と回復率を出す | 生成 約 1,500 本、数時間 |
| 3 | 全層の残差を保存し、段 1・2a・2b のプローブを学習 | forward のみ、数時間 |
| 4 | 活性パッチングと方向注入 | 生成 数千本、1 日 |
| 5 | （余力）SAE と接地 | 学習 1 日 |

backward は不要で、J-lens の fit（15 時間）より軽い。実装 2〜3 週間、実験 2〜3 週間が目安。

### 3.4 注意点

- テキスト位置の残差は T5 の段階で文脈が混ざっているので、「単語そのもの」ではなく「その語によって変わった状態」を扱っている。対で比べる限り差分は属性に帰属できる。
- 生成は確率的なので、1 プロンプトあたり複数サンプル（例 5 本）で実現率を取る。
- 実現率の判定しきい値は val の実データ（属性語を含むキャプションの動き）で較正する。
- プロンプト集は MotionMillion の学習分布に近いもの（MotionMillion-Eval）と、外（T2MBench）の両方を入れ、分布外での F1/F3 の違いを見る。
