## 4. Architecture 全体像

論文の主張：大規模なモーションデータセットを土台に、**zero-shot（学習で見ていない文章にも汎化）**
できる基盤モデルを作りたい。自然言語・画像で成功した**スケーリング戦略**を真似て、
**離散自己回帰（discrete autoregressive）アーキテクチャ**を採用する。

モデルは大きく **2 段** に分かれます。

| ステージ | 名前 | 役割 | 本ドキュメントの節 |
|----------|------|------|--------------------|
| 1 | **Efficient Motion Tokenization**（効率的なモーションのトークン化） | FSQ で連続モーション → 離散トークンへ圧縮 | 4.2 |
| 2 | **Scalable Motion Generation**（スケーラブルなモーション生成） | LLAMA でテキスト条件付きにトークン列を生成 | 4.3 |

その入力となるデータ形式の定義が 4.1 です。

```
   テキスト ─► [T5-XL] ─┐
                        ▼
   モーション ─► [FSQ Encoder] ─► トークン ─► [LLAMA 自己回帰] ─► トークン ─► [FSQ Decoder] ─► モーション
        (4.1 の表現)        (4.2)                          (4.3)
```

## 4.1 Motion Representations（モーションの表現）

### 直感的な説明

モーションを**どんな数値ベクトルで表すか**を決める節です。
従来の HumanML3D 形式は、逆運動学（Inverse Kinematics, IK）に由来する誤差や、
回転表現の誤りを抱えていました。本論文は、character control 分野の先行研究にならい、
**冗長だが扱いやすい表現**を再設計します。

各フレームのポーズ $x_i$ を、次の要素を連結したタプルとして定義します。

### 数式

$$
x_i = \{\, \dot r_x,\ \dot r_z,\ \dot r_a,\ p_i,\ v_i,\ r_i \,\}
$$

### 記号の説明

| 記号 | 意味 | 次元 | 補足 |
|------|------|------|------|
| $\dot r_x,\ \dot r_z$ | ルート（腰）の XZ 平面上の**並進速度** | $\mathbb{R}^1$ ×2 = 2 | 水平面内の移動速度 |
| $\dot r_a$ | ルートの**角速度（向きの変化）** | $\mathbb{R}^6$ | 6D 回転表現で表す |
| $p_i$ | 各関節の**ローカル位置** | $\mathbb{R}^{3N}$ | ルート基準。$3 \times N$ |
| $v_i$ | 各関節の**ローカル速度** | $\mathbb{R}^{3N}$ | $3 \times N$ |
| $r_i$ | 各関節の**ローカル回転** | $\mathbb{R}^{6N}$ | 6D 回転表現。$6 \times N$ |
| $N$ | **関節数** | — | 本実装では $N = 22$ |
| $i$ | フレーム番号 | — | $i$ 番目のフレーム |

合計次元：$2 + 6 + 3N + 3N + 6N = 8 + 12N$。$N=22$ なら $8 + 264 = \mathbf{272}$ 次元。
これがリポジトリで `vector_272` と呼ばれる表現です。

### この表現の利点（論文より）

- **IK 不要**：位置と回転の両方を持つので、SMPL / BVH へ直接変換でき、逆運動学が要らない。
- **可逆**：SMPL の相対回転へ**ロスレス変換**できる。
- **相互正則化**：位置成分と回転成分が同じ骨格から導かれるので、互いに整合性チェックが効く。
- HumanML3D の**回転成分の誤り**を、破棄せず工学的に修正している。

### 実装状況

| 項目 | 実装場所 | 内容 |
|------|----------|------|
| 272 次元の生成 | データ前処理（リポジトリ外、配布データ `motion_data/vector_272/*.npy`） | shape = `(フレーム数, 272)` |
| 入力次元の指定 | `models/vqvae.py:37,40` | `251 if kit else 272` |
| 272 → 位置/回転の復元 | `inference_single.py:80-140` | `recover_from_local_position()` / `recover_from_local_rotation()` |
| 正規化用統計 | `dataset/MotionMillion/mean_std/vector_272/{mean,std}.npy` | Z 正規化に使用 |

実装上のベクトルの並び（`inference_single.py` の復元コードから逆算）：

| 範囲 | 対応する記号 |
|------|--------------|
| `[0:2]` | $\dot r_x, \dot r_z$ |
| `[2:8]` | $\dot r_a$（6D） |
| `[8:8+3N]` = `[8:74]` | $p_i$ |
| `[8+3N:8+6N]` = `[74:140]` | $v_i$ |
| `[8+6N:8+12N]` = `[140:272]` | $r_i$（6D） |

## 4.2 Efficient Motion Tokenization（FSQ によるトークン化）

### 直感的な説明

連続値のモーションを、後段の LLAMA が扱える**離散的な整数 ID（トークン）**に変換します。
通常の VQ-VAE は「コードブック（埋め込み表）」を持ち、最も近いコードを探す距離計算が必要ですが、
本論文は **FSQ（Finite Scalar Quantization, 有限スカラー量子化）** を採用します。
FSQ は**コードブックを持たず**、各次元を決められた段階に「丸める」だけで離散化するため、
大規模データでも安定し、コードの利用率が高い（codebook collapse が起きにくい）のが利点です。

### FSQ の 3 ステップ（論文の説明）

1. モーション・エンコーダが潜在ベクトル $z$ を出す。
2. $z$ を関数 $f$ で**有界な範囲 $[0,1]$ に正規化**する（論文では sigmoid と記載）。
3. 各次元を $L$ 段階に**丸めて離散化**する。

### 数式

**量子化（式 3）:**

$$
\hat z = Q(z) = \mathrm{round}\big(f(z)\cdot(L-1)\big)
$$

これにより離散コード $\hat z \in \{0,1,\dots,L-1\}^d$ が得られます。
VQ-VAE のように物理的な埋め込みを保存する必要がなく、$L^d$ 個のコードを**暗黙的に**（格子状に）定義します。

**学習の損失（式 4）:**

$$
\mathcal{L} = \lVert m - \mathrm{Dec}(z_q) \rVert_2^2
$$

再構成損失**のみ**で学習し、VQ-VAE で必要だった補助損失（コードブック commitment 項など）を**除去**します。

### 記号の説明

| 記号 | 意味 | 補足 |
|------|------|------|
| $z$ | モーション・エンコーダが出力する**潜在ベクトル** | 連続値 |
| $f(\cdot)$ | $z$ を $[0,1]$ に押し込む**正規化関数** | 論文では sigmoid（実装は tanh ベース、後述） |
| $L$ | 1 次元あたりの**量子化レベル数** | 次元ごとに異なる値を取りうる |
| $d$ | 潜在の**次元数**（量子化する次元の数） | コード長 |
| $\hat z$ | 離散化された**コード** | $\{0,\dots,L-1\}^d$ |
| $Q(\cdot)$ | 量子化関数 | round 操作を含む |
| $z_q$ | 量子化後に逆射影した**潜在** | デコーダ入力 |
| $m$ | 入力モーション（再構成のターゲット） | グラウンドトゥルース |
| $\mathrm{Dec}(\cdot)$ | モーション・デコーダ | $z_q$ → モーション |
| $L^d$ | コードブックの**総コード数**（語彙サイズ） | 物理的には保存しない |

本実装では、$d=6$、各次元のレベルを $L = [8,8,8,5,5,5]$ とすることで、
語彙サイズ $L^d = 8\times8\times8\times5\times5\times5 = \mathbf{65536}$ を実現します。

### 実装状況

FSQ は `models/FSQ.py` に実装されています。**論文の式と実装には以下の差異**があります（初学者は要注意）。

| 論文の記述 | 実際の実装 | 場所 | コメント |
|------------|------------|------|----------|
| $f$ = **sigmoid** で $[0,1]$ に正規化 | **tanh ベースの `bound()`** で $[-L/2, L/2]$ 付近に有界化 | `FSQ.py:106-117` | 数学的には等価な「有界化＋丸め」。論文の説明は簡略化された一般論 |
| `round`（式3） | **`round_ste`**（straight-through で勾配を通す丸め） | `FSQ.py:46-49,113-117` | 丸めは微分不可なので勾配は恒等として流す |
| 損失 = **L2 二乗誤差**（式4）のみ | **L1 smooth 再構成損失 + 速度損失**（+任意で加速度損失） | `train_tokenizer.py:139-158` | 実装はより滑らかさを重視。FSQ なので commitment 損失は無い点は式4と一致 |
| レベル $L$ | `nb_code` に応じて `levels` を選択 | `models/vqvae.py:55-72` | 65536 → `[8,8,8,5,5,5]` |
| コード ID 化 | `_basis`（各レベルの累積積）との内積で 1 整数 ID に変換 | `FSQ.py:71,132-136` | 多次元コード → 単一整数トークン |

FSQ の主なメソッド：

- `forward(z)`: 量子化して `(out, indices, ...)` を返す（`FSQ.py:179-249`）。
- `codes_to_indices` / `indices_to_codes`: コード ⇄ 整数 ID の相互変換。
- `dequantize(indices)`: 整数 ID → 連続潜在（デコード時に使用）。

## 4.2 補足：Wavelet Transformation（ウェーブレット変換）

### 直感的な説明

論文では 4.2 と 4.3 の間で、FSQ の**重要な改良**として **ウェーブレット変換**を導入します。

> 素の FSQ（w/o wavelet）は、離散化による情報損失で**高周波成分のモデル化に誤差**が出て、
> 再構成モーションに**激しいジッタ（小刻みな震え）**が生じる。

そこで、

- **エンコーダの入口**でモーションに**ウェーブレット変換**を掛け、
- **デコーダの出口**で**逆ウェーブレット変換**で元に戻す。

ことで、高周波の損失を抑えジッタを大幅に低減します（論文 Table 3 のアブレーション）。

### 効果（論文 Table 3）

| 設定 | MPJPE ↓ | Mean Acc ↓ | Max Acc ↓ |
|------|---------|------------|-----------|
| GT（正解） | − | 2.0 | 9.0 |
| w/o wavelet（ウェーブレットなし） | 46.8 | 6.0 | 15.0 |
| **w/ wavelet（あり）** | **45.5** | **4.0** | **12.0** |

> Acc（加速度）が GT に近いほどジッタが少ない＝滑らか。ウェーブレット導入で MPJPE もわずかに改善。

### 実装状況

| 項目 | 実装場所 | 内容 |
|------|----------|------|
| 順変換（エンコーダ入口） | `models/encdec.py:115-116`（`Patcher1D`） | Encoder の先頭に挿入 |
| 逆変換（デコーダ出口） | `models/encdec.py:170-171`（`UnPatcher1D`） | Decoder の末尾に挿入 |
| Haar ウェーブレット本体 | `models/modules.py:122-242` | `_dwt`（離散ウェーブレット変換）/ `_idwt`（逆変換）を Conv1d で実装 |
| 有効化フラグ | 各 `scripts/*/*.sh` の `--use_patcher --patch_size 1 --patch_method haar` | これらを消すとウェーブレット無効 |

仕組み（`modules.py`）：Haar フィルタで**低周波 `xl`（平滑）と高周波 `xh`（ディテール）に分離**し、
チャネル方向に連結します（`_dwt`）。低域通過 `hl` と高域通過 `hh = h·(−1)^k` の 2 フィルタを
`F.conv1d(..., stride=2)` で適用。逆変換 `_idwt` は `F.conv_transpose1d` で復元します。
このフィルタ重みは学習しません（`requires_grad=False`, `modules.py:136-137`）。

## 4.3 Scalable Motion Generation（スケーラブルなモーション生成）

### 直感的な説明

ここが**生成本体**です。**transformer-decoder ベース（LLAMA）**で、
テキストを条件にモーション・トークンを**自己回帰的に**（1 個ずつ）生成します。

- モーションは **FSQ** で圧縮・トークン化。
- テキストは **T5-XL** で**単語レベル**にエンコード。
- エンコードされたテキストとモーションを **Hybrid Attention Block (HAB)** の積み重ねに通し、
  最後に**分類ヘッド（classification head）**で次トークンを予測。

### 数式・記法

エンコードされたモーションとテキストを次のように表します。

$$
\{m_i\}_{i=1}^{n}, \qquad \{T_i\}_{i=1}^{w}
$$

### 記号の説明

| 記号 | 意味 |
|------|------|
| $m_i$ | $i$ 番目の**モーション・トークン**（FSQ で得た離散 ID） |
| $n$ | **モーション・トークンの数**（系列長） |
| $T_i$ | $i$ 番目の**単語トークン**（T5-XL の単語レベル埋め込み） |
| $w$ | **単語トークンの数** |

### Hybrid Attention Block (HAB) の構成

論文によると、各 HAB は次の 3 要素から成ります。

| 要素 | 個数 | 役割 |
|------|------|------|
| **RMS-Norm 層** | 2 | 学習の不安定性を大幅に緩和 |
| **Mixed Attention（混合注意）モジュール** | 1 | テキストとモーションの複雑な関係を捉える |
| **FFN（フィードフォワード）** | 1 | 各位置の特徴を非線形変換 |

```
      入力 x
        │
   ┌────┴─────────────────┐
   │   RMSNorm → MixedAttention   │ ─(残差)─► +
   │   RMSNorm → FFN              │ ─(残差)─► +
   └──────────────────────┘
        │
      出力 → … → 分類ヘッド（次トークン予測）
```

### Mixed（Hybrid）Attention の鍵

通常の transformer は全位置で因果（causal）注意ですが、本手法は **混合戦略**を取ります。

| 対象 | 注意の種類 | 意味 |
|------|------------|------|
| **単語 ↔ 単語** | **双方向（bidirectional）** | 文章全体を一度に見られる（文脈理解） |
| **モーション ↔ モーション** | **因果（causal）** | 未来のトークンは見られない（自己回帰生成のため） |

### 記号・ハイパーパラメータ（モデルサイズ）

| 名前 | レイヤ数 $n_{layer}$ | ヘッド数 $n_{head}$ | 埋め込み次元 $n_{embd}$ |
|------|---------------------|---------------------|-------------------------|
| 3B | 24 | 32 | 3200 |
| 7B | 36 | 32 | 4096 |

論文では 1B〜7B までスケールさせ、**大きいほど zero-shot 性能が向上**（Table 4: FID が 31.3→10.3）。

### 実装状況

LLAMA 本体は `models/lit_llama/model_hf.py` の `LLaMAHF` クラスに実装されています。

| 論文の要素 | 実装 | 場所 |
|------------|------|------|
| テキストの単語レベルエンコード（T5-XL） | `T5EncoderModel`（flan-t5-xl, `clip_dim=2048`） | `train_t2m_llama.py:172-180` |
| HAB（積み重ねブロック） | `Block`（`config.n_layer` 個） | `model_hf.py:55-58, 465-488` |
| RMS-Norm ×2 | `rms_1`, `rms_2`（`RMSNorm`） | `model_hf.py:468,471,612-632` |
| Mixed Attention | `LengthCausalSelfAttention`（下記マスク） | `model_hf.py:539-590` |
| FFN | `MLP`（SwiGLU: `silu(c_fc1(x))*c_fc2(x)`） | `model_hf.py:593-609` |
| 位置エンコード | **RoPE**（回転位置埋め込み） | `model_hf.py:635-677` |
| 分類ヘッド | `lm_head`（`Linear` → 語彙サイズ） | `model_hf.py:54,155` |
| テキスト埋め込みの射影 | `llama_proj`（2048 → `n_embd`） | `model_hf.py:63` |
| モデルサイズ定義 | `llama_configs`（3B/7B 等） | `model_hf.py:31-44` |

**Mixed Attention のマスク実装**（`model_hf.py:577-584`）が論文の「単語=双方向／モーション=因果」を表現します。

```python
# 下三角（因果）マスク：自分より過去だけ見える
attn_mask = torch.tril(torch.ones(T, T, ...))
# テキスト同士は全結合（双方向）にするマスク
text_mask = y_mask.unsqueeze(2) * y_mask.unsqueeze(1)
text_mask = F.pad(text_mask, ...)
# 2つを OR で合成 → テキスト部は双方向、モーション部は因果のまま
attn_mask = torch.logical_or(attn_mask, text_mask)
y = F.scaled_dot_product_attention(q, k, v, attn_mask=attn_mask.unsqueeze(1), is_causal=False)
```

**語彙サイズ**は `nb_code + 2`（`train_t2m_llama.py:216`）：

| ID | 意味 |
|----|------|
| `0 .. 65535` | 通常のモーション・トークン（FSQ の 65536 種） |
| `65536` | End（系列終端）トークン |
| `65537` | Pad（パディング）トークン |

### 学習と推論（4.3 の式は明示されないが、実装上は次トークン予測）

- **学習**：クロスエントロピーで「次のトークン」を予測。Pad は無視。

$$
\mathcal{L}_{\text{gen}} = \mathrm{CrossEntropy}\big(\text{logits}_{[:-1]},\ \text{tokens}_{[1:]}\big)
$$

実装：`train_t2m_llama.py:296,336-339`（`ignore_index = nb_code+1` で Pad を無視）。

- **推論**：空列から開始し、End が出るか最大長まで 1 トークンずつ生成（`LLaMAHF.sample`, `model_hf.py:102-136`）。

## まとめ：第4章の全体マップ

```
[4.1 表現]  各フレーム xi = {ṙx, ṙz, ṙa, pi, vi, ri}  → 272次元 (N=22)
                  │
                  ▼  wavelet 変換（4.2補足, modules.py）
[4.2 トークン化]  Encoder → FSQ:  ẑ = round(f(z)(L-1))  (式3),  L=[8,8,8,5,5,5], 語彙65536
                  損失  L = ||m - Dec(zq)||²  (式4)  ← 実装はL1smooth+速度損失
                  │ inverse wavelet
                  ▼
[4.3 生成]  T5-XL(テキスト) + FSQトークン → Hybrid Attention Block×N → 分類ヘッド
                  Mixed Attention: 単語=双方向 / モーション=因果
                  3B(24層/3200) , 7B(36層/4096) , RoPE + RMSNorm + SwiGLU
```
