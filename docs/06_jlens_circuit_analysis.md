# Jacobian Lens / Global Workspace 的手法で MotionMillion の「思考回路」を覗けるか

対象：[Verbalizable Representations Form a Global Workspace in Language Models](https://transformer-circuits.pub/2026/workspace/index.html)（Transformer Circuits, 2026）の手法を、本リポジトリの text-to-motion モデルに適用できるか。

**結論を先に**：

> **部分的に「できる」。ただし論文そのままの形では**できない**。**
>
> J-lens の中核は「残差ストリーム → 語彙ロジット」という写像を作り、内部表現を**語彙という人間可読な軸に射影**することにある。
> 本モデルにはその写像（`lm_head`）が**確かに存在する**が、その語彙は英単語ではなく **65,536 個の FSQ モーション・トークン**である。
>
> したがって得られるのは「モデルが**何を言おうとしているか**」ではなく、
> **「モデルが今どんな動きを出そうとしているか（poised to move）」** である。
> 論文の言う *verbalizable*（言語化可能）は成立しないが、その motion 版 ―― 本ドキュメントで **"M-lens"** と呼ぶ ―― は成立する。
>
> そして**最大の障害はテキスト側にある**：テキストは**トークンではなく T5 埋め込みとして注入される**ため、
> テキスト位置には unembedding が存在せず、**テキスト概念を語彙軸で読み出すことは原理的にできない**。

> 関連：SAE ベースの分析可否は `docs/03_sae_query_motion_analysis.md` に既にまとめてある。
> 本ドキュメントはその**姉妹編**で、SAE（辞書学習）ではなく **J-lens（勾配ベースの線形読み出し）**という別系統の手法を扱う。

---

## 1. J-lens とは何か（3行で）

論文の手法を最小限に要約する。

各層 ℓ の残差ストリーム $h_\ell$ が、最終層 $h_{final}$ にどう影響するかを**一次近似（ヤコビアン）**で捉える：

$$
J_\ell \;=\; \mathbb{E}_{t,\; t' \ge t,\; \text{prompt}} \left[ \frac{\partial h_{final,\,t'}}{\partial h_{\ell,\,t}} \right]
$$

これを unembedding $W_U$ と組み合わせ、中間層の活性を**語彙上の分布**として読み出す：

$$
\mathrm{lens}(h_\ell) \;=\; \mathrm{softmax}\big(W_U \cdot \mathrm{norm}(J_\ell\, h_\ell)\big)
$$

| 特徴 | 内容 |
|------|------|
| 必要なもの | 順伝播・逆伝播、**unembedding 行列 $W_U$**、残差ストリーム |
| 不要なもの | **SAE / transcoder / CLT は不要**（生の残差ストリームだけで動く） |
| コスト | 約 1,000 プロンプトでヤコビアンを平均 |
| 介入 | steering（$h \leftarrow h + \alpha v_t$）、lens 座標での patching、top-k 方向の ablation |
| 論文の制約 | 単一トークン概念のみ／前1/3の層は「ノイジーで解釈不能」／**語彙で添字づけされた $W_U$ が必須** |

**Logit Lens との違い**：Logit Lens は $W_U h_\ell$ をそのまま見る（層をスキップする＝残りの層の処理を無視する）。
J-lens は $J_\ell$ を挟むことで「**残りの層を通過したあとの効果**」を一次近似で織り込む。これが精度差になる。

**なぜ SAE より魅力的か**：SAE は数百万サンプルでの**別途の学習**が必要（`docs/03` の B1）。
J-lens は**学習不要**で、ヤコビアンを平均するだけ。**本リポジトリにとってはこれが決定的に有利**（後述）。

## 2. 本モデルの構造 ―― 何が有利で何が致命的か

`models/lit_llama/model_hf.py` の forward が全てを物語る（`model_hf.py:159-183`）：

```python
def forward(self, idx, clip_feature, y_mask):
    text_length = clip_feature.shape[1]
    x = self.transformer.wte(idx)                      # モーション・トークンの埋め込み

    # ★ テキスト位置を T5 埋め込みの射影で「上書き」する
    expanded_mask = y_mask.unsqueeze(-1).expand(-1, -1, x.shape[-1])
    result = torch.where(expanded_mask == 1,
                         self.llama_proj(clip_feature),  # ← T5-XL 埋め込み → n_embd に射影
                         x[:, :text_length, :])
    x = torch.cat((result, x[:, text_length:, :]), dim=1)

    for block in self.transformer.h:                    # ← 各層でフック可能
        x = block(x, y_mask)
    x = self.transformer.ln_f(x)
    logits = self.lm_head(x)                            # ← ★ unembedding は存在する
```

ここから読み取れる**3つの決定的事実**：

### 事実1（有利）：`lm_head` は本物の unembedding である

```python
self.lm_head = nn.Linear(config.n_embd, config.vocab_size - 1, bias=False)   # model_hf.py:54
```

**J-lens が要求する $W_U$ はここに実在する。** 数式は一字も変えずに適用できる。
ただし語彙軸は**単語ではなくモーション・トークン**である。

### 事実2（致命的）：テキストには unembedding が無い

テキストは `wte`（埋め込みテーブル）を通らない。`llama_proj(clip_feature)` で**直接注入**される。
つまり：

- テキスト位置の残差ストリームを $W_U$ で読み出しても、**返ってくるのはモーション・トークンの分布**であって、単語ではない。
- 「モデルは今 *run* という概念を持っているか？」を**語彙軸で問うことはできない**。$W_U$ に *run* という行が存在しないからだ。

**これが論文手法をそのまま移植できない核心的理由**であり、本レポートの最大のボトルネックである（§4 B1）。

### 事実3（有利）：注意マスクがテキスト↔モーションの情報経路を明示している

```python
attn_mask = torch.tril(torch.ones(T, T))                     # モーション側：因果
text_mask = y_mask.unsqueeze(2) * y_mask.unsqueeze(1)        # テキスト側：双方向
attn_mask = torch.logical_or(attn_mask, text_mask)           # model_hf.py:575-582
```

テキストは**先頭に固まって双方向**、モーションは**因果**。
**位置インデックスだけでモダリティが完全に分離できる**（`y_mask.sum()` 個までがテキスト）。
これは「テキスト → モーション」の因果経路を追跡する上で**極めて好都合**である。

### 事実4（有利・重要）：FSQ の語彙は「構造化された格子」である

`models/vqvae.py:68-69`：

```python
elif args.nb_code == 65536:
    levels = [8, 8, 8, 5, 5, 5]      # 8×8×8×5×5×5 = 65,536
```

これが本モデル最大の幸運である。**65,536 トークンは恣意的な ID ではない。**
FSQ（Finite Scalar Quantization）の語彙は **6 次元の直積格子**で、
トークン ID は 6 個の独立したスカラー水準に**可逆に分解できる**（`FSQ.py:138-142`）：

```python
def indices_to_level_indices(self, indices):
    codes_non_centered = (indices // self._basis) % self._levels    # ID → 6次元の水準
    return codes_non_centered
```

さらに `indices_to_codes()`（`FSQ.py:144`）で**学習済みコードブックの参照なしに**、
任意のトークン ID から連続コードを解析的に復元できる（FSQ は**暗黙のコードブック**を持つ）。

補足：`num_codebooks = 1` なので**残差 VQ ではなく、1 時刻 = 1 トークン**。
30fps・`--down-t 1`（2倍ダウンサンプル）なので **約 15 トークン/秒**。解析の単位が素直である。

**なぜこれが効くか**：LLM の語彙（"cat", "run"）は互いに**無関係な離散シンボル**で、
65,536 個の logit を人間が眺めても意味を成さない。
だが FSQ 語彙は**距離が定義された連続空間の離散化**なので：

- 65,536 次元の logit ベクトルを **6 次元の解釈可能な座標に射影**できる。
- 「この特徴はモーション格子のどの軸を動かすか」という形で**低次元に要約できる**。
- **これが `docs/03` の B7（「語彙が巨大すぎて直感的でない」）に対する、SAE には無い回答である。**

## 3. できること ―― 具体的な3つの分析

### 3.1 M-lens：「モデルは今どんな動きを出そうとしているか」

J-lens をそのまま motion 語彙に適用する。得られるのは：

> 生成のステップ $t$、層 $\ell$ において、**モデルが出力に向けて用意している動き**

論文の *"poised to say"*（言おうとしている）が、ここでは *"poised to move"*（動こうとしている）になる。

**具体的に見えるもの**：
- **どの層で動きが決まるか**：浅い層ではまだ動きが未定で、深い層で特定の動きに収束していく過程を層ごとに可視化できる。論文が「前1/3の層はノイジー」と言うのと同じ現象が起きるかを検証できる。
- **先読み（lookahead）**：ヤコビアンは $t' \ge t$ にわたる将来位置への効果を平均するので、「今の内部状態が**何ステップ先の動きまで**を決めているか」が測れる。走り出す前に既に着地が決まっているか、といった問い。
- **65,536 次元 → 6 次元**：出てきた logit 分布を FSQ 格子の 6 軸に射影して読む（§2 事実4）。

**なぜ検証できるか（本リポジトリの強み）**：M-lens が「この動きを出そうとしている」と予測したら、
その予測トークンを `forward_decoder`（`vqvae.py:127`）に通して**実際に動画としてレンダリングできる**（`inference_single.py`）。
つまり **lens の読み出しが正しいかを目で確認する経路が既にある**。
言語モデルの解釈では「特徴の意味づけ」が人手評価に依存しがちだが、ここでは**デコードして見れば分かる**。これは大きな利点である。

### 3.2 ★ テキスト → モーションの関係を覗く（ご要望の核心）

「モーションとテキストの関係を覗けたら good」とのことなので、ここを厚く書く。

論文の手法は**そのままでは使えない**（テキストに $W_U$ が無い、§2 事実2）。
だが**方向を逆にすれば使える**。以下が現実的で、しかも本モデルの構造に適合する。

#### 手法A：Motion-vocabulary Jacobian（テキスト位置 → モーション語彙）★推奨

テキスト位置 $p$（`y_mask` で特定できる）の残差ストリーム $h_{\ell,p}$ から、
**モーション語彙のロジット**へのヤコビアンを取る：

$$
J^{\text{text}\to\text{motion}}_{\ell,\,p} \;=\; \frac{\partial\, \text{logits}_{\text{motion},\,t'}}{\partial\, h_{\ell,\,p}}
\qquad (p \in \text{text},\; t' \in \text{motion})
$$

これが答える問い：

> **「プロンプトのどの単語位置が、どのモーション・トークンを、どれだけ引き起こしているか」**

- 「a person **runs** quickly」の *runs* の位置を微小変化させると、どのモーション・トークンのロジットが動くか。
- その反応したトークンを **FSQ でデコードして可視化**すれば、「*runs* が引き起こす動き」が**映像として**見える。
- 副詞（*quickly*）と動詞（*runs*）で、影響する FSQ 軸が違うか。速度が特定の軸に乗っているか。

これは J-lens の**素直な変形**であり（ヤコビアンの始点をテキスト位置に、終点を motion logit にするだけ）、
論文の計算機構をほぼそのまま流用できる。**しかもテキストと動きが位置で綺麗に分離しているため実装が容易**（§2 事実3）。

#### 手法B：Steering（介入による因果検証）

論文の steering（$h \leftarrow h + \alpha v$）をテキスト位置に対して行う。

- 手法A で得た方向 $v$（あるテキスト位置がモーションに効く方向）に沿って活性を加減し、
- **生成される動きが実際に変わるか**をデコードして確認する。

これが `docs/03` の **B3（相関 vs 因果）に対する直接的な回答**になる。
SAE は相関しか出さないが、**steering は介入なので因果が言える**。
そして本モデルでは「因果効果」が**動画として目に見える**ので、検証が異様にやりやすい。

#### 手法C：注意経路の追跡（補助）

`model_hf.py:582` の `attn_mask` を使い、モーション位置がテキスト位置のどこを見ているかを層・ヘッドごとに集計する。
`F.scaled_dot_product_attention` は注意重みを返さないので、**そこだけ手書き実装への差し替えが必要**（軽微な改造）。
手法A/B の裏付け（どの経路を通って効いているか）として使う。

### 3.3 「ワークスペース」仮説そのものの検証

論文の主張は「少数の特権的な表現が広域に broadcast される」というもの。
本モデルで対応する問いは：

> **テキストの意味は、少数の低次元方向に圧縮されてモーション生成に broadcast されているのか？**

`llama_proj`（`model_hf.py:63`）は T5 の 2048 次元を n_embd（3B なら 3200 / 7B なら 4096）へ射影する**唯一の関門**である。
**テキストからモーションへの情報は、必ずこの 1 枚の線形層を通る。**
その特異値スペクトルを見れば「実効的に何次元が使われているか」が即座に分かる ―― これは**ボトルネックが構造的に明示されている**という意味で、
言語モデルより**むしろ分析しやすい**。論文が苦労して探す「ワークスペース」が、ここでは**アーキテクチャ上に露出している**。

| **B2** | **「言語化可能性」の概念が成立しない** | 原理 | 高 | 本モデルは喋らない。論文の5つの機能的性質のうち検証できるのは一部のみ |

### B9：テキスト前置部が双方向であることの落とし穴

`attn_mask` の `logical_or`（`model_hf.py:575-582`）により、**テキスト・ブロック内は双方向注意**である。
これは手法A/B に効いてくる：

- 「*runs* の位置だけを steering する」という介入をしても、その効果は**同じ層内で全テキスト位置に伝播する**。
- したがって「単語 *runs* の寄与」を**単独で切り出すのは素朴には不可能**。
- 実務的には、位置ごとの寄与ではなく「**プロンプト全体の摂動 → モーションの変化**」として測るか、
  層 0（注意の前）で介入して伝播を追う、という設計にするのが安全。

「単語 → 動き」という綺麗な一対一対応を期待しすぎない、という戒めである。

### B1：テキスト側に unembedding が無い ― 最大かつ原理的な壁

繰り返すが、これが本質である。

論文の J-lens は「$W_U$ の各行 = 1つの語彙トークン = 人間が読める概念」という対応に**全面的に依存**している。
本モデルのテキストは `llama_proj(clip_feature)` として注入されるため、**テキスト概念に対応する $W_U$ の行が存在しない。**

**回避策と、その限界**：

| 回避策 | 内容 | 限界 |
|--------|------|------|
| 手法A（推奨） | 方向を逆にし、テキスト位置 → **モーション語彙**のヤコビアンを取る | 「テキストが何を引き起こすか」は分かるが、「テキストが何を表現しているか」は分からない |
| T5 の語彙を借りる | T5-XL の unembedding を $W_U$ の代用にする | **射影 `llama_proj` を跨ぐため理論的保証が無い**。T5 空間と LLAMA 空間は別物 |
| プローブを学習する | テキスト位置の活性から単語を予測する線形プローブを別途学習 | **もはや J-lens ではない**（学習不要という利点を失う）。SAE と同程度のコストに戻る |

**率直に言えば**：「テキスト概念を語彙軸で読む」という論文の目玉機能は、
このアーキテクチャでは**綺麗には再現できない**。ここは正直に諦めて、**手法A（逆方向）に振るのが賢い**。

### B2：「言語化可能性」が成立しない

論文の主題は *verbalizable*（モデルが**口に出せる**表現）である。
本モデルは動きしか出力しない ―― **口が無い**。
したがって論文の5つの機能的性質のうち：

| 論文の性質 | 本モデルでの成否 |
|------------|------------------|
| Verbal report（言語報告） | **✗ 不可能**（出力語彙が動きなので） |
| Directed modulation（steering で操作できる） | **○ 可能**（手法B） |
| Internal reasoning（出力に出ない内部推論） | **△ 部分的**（「動きに出ない内部状態」は定義可能） |
| Flexible generalization | **○ 可能**（zero-shot が売りのモデルなので、むしろ好適） |
| Selectivity | **○ 可能** |

**"Global Workspace" という論文の主張そのもの**（少数の特権的表現が broadcast される）は
§3.3 の形で**検証可能**だが、その中身は「言語化可能な表現」ではなく
「**モーション生成を制御する低次元の意味表現**」に読み替わる。これは別の主張である。
**論文の追試ではなく、類推による新規研究**だと理解しておくのが正しい。

### B3：重みが無い

現時点でリポジトリ内に学習済み重みは**1つも無い**（`find` で確認済み）。
必要なのは：7B（または 3B）の LLAMA 本体、FSQ tokenizer、**flan-t5-xl**（`scripts/train/train_t2m_7B.sh:31` が既定）。
まずここを解決しないと何も始まらない。**3B から始めるべき**（`model_hf.py:37`、24層×3200次元）。

### B4：計算コスト ― ただし SAE より遥かに軽い

**ここは朗報である。** `docs/03` では B1（SAE 学習コスト）が最大のボトルネックだったが、
**J-lens は学習を必要としない**。約1,000プロンプト分の逆伝播を層ごとに平均するだけで済む。

- SAE：数百万活性サンプルの収集 ＋ 辞書の学習（ハイパラ調整、dead feature 対策…）
- J-lens：**1,000プロンプト × 層数の逆伝播、以上**

**つまり J-lens は「SAE をやる前に試すべき、圧倒的に安い手法」である。**
これが本レポートの実務上の最重要の示唆かもしれない。

## 5. 現実的なロードマップ（安い順）

## 6. まとめ

- **論文手法をそのまま適用できるか → NO。** 中核である「語彙軸での読み出し」は、
  **テキストがトークンではなく T5 埋め込みとして注入される**ため、テキスト側には成立しない（**B1、最大の壁**）。
  論文の主題である *verbalizable*（言語化可能性）は、**口を持たない**このモデルでは定義できない（B2）。

- **では何ができるか → 方向を逆にすれば、かなり多くのことができる。**
  - `lm_head` は**実在する**（`model_hf.py:54`）ので、J-lens の数式は**モーション語彙に対してそのまま動く**。
  - FSQ 語彙は **8×8×8×5×5×5 の構造化格子**（`vqvae.py:68`）なので、65,536 次元を**6 次元に射影して解釈できる**。
    これは LLM の語彙には無い性質で、**巨大語彙という一見の弱点が、実は強みに反転している**。
  - テキストとモーションが**位置で完全に分離**している（`model_hf.py:575-582`）ため、
    **「テキスト位置 → モーション語彙」のヤコビアン**（手法A）が素直に書ける。これが**ご要望の「テキストとモーションの関係」に直接答える**。
  - **steering**（手法B）で相関ではなく**因果**が言える。しかも効果が**動画として目視できる**。

- **実務上の最重要の示唆**：**J-lens は SAE より圧倒的に安い**（学習不要 vs 数百万サンプルの辞書学習）。
  `docs/03` で SAE の最大の壁とした計算コストを、J-lens は**回避できる**。
  **SAE の前に J-lens を試すべき**である。

- **最初の一手**：`llama_proj` の特異値分解（段階0）。
  テキストからモーションへの情報は**この 1 枚の線形層を必ず通る**ので、
  そのスペクトルは「テキストの意味が実効何次元に圧縮されているか」を**重みさえ入手できれば即日**教えてくれる。
  論文が苦労して探す「ワークスペース」が、**このアーキテクチャでは構造として露出している** ―― ここが本モデル最大の面白さだと思う。

- **ただし前提**：学習済み重みが**現在リポジトリに1つも無い**（B3）。まず 3B ＋ FSQ ＋ flan-t5-xl の入手から。
